IPRC1000 原生内核 v0.4.44
========================

适用遥控器：Verizon FiOS IPTV 遥控器（型号 IPRC1000，博通 BCM20734，蓝牙+红外双模）。
认不准就看背面左下角：印着 RC3602301/02BR 与蓝牙 MAC 的就是它。

★ 换机器 / 换遥控器后第一件事：**不要改造遥控器**。
   遥控器保持「键盘」身份时，蓝牙 HID 中断通道才会建立，程序才收得到按键。
   旧说明里的「④ 改造遥控器（改成 HID-compliant / raw）」会让接口消失，
   按键与语音会全部收不到 —— 这是 2026-11-06 真机确认的结论。
   已经改造过的机器：运行 IPRC1000-Native.exe --restore-keyboard 恢复，
   或打开「环境与安装」点 **④ 恢复键盘模式**；恢复后**还要按一下遥控器唤醒，
   或禁用/启用一次蓝牙适配器**（删节点后 Windows 不会在链路未断时自己重建）。
   代价：不改造时系统会同时往光标处打字母（已知边界，不影响映射/宏/语音生效）。

一、这是什么
   用 Rust 重写的遥控器适配器（egui 界面，无 WebView2）。
   体积小、内存低、不依赖 .NET 运行时。

   ⚠ 从旧版（C# 版，界面是网页风格那个）换过来的用户请注意：
       **两版的配置文件不通用，键位 / 宏 / 文本槽需要重新设置一遍。**
       C# 版的 settings.json 不会被导入，也不会删除。

   配置和日志都在**程序目录**下（不再散落到 AppData）：
       <程序目录>\data\   native.json / shortcuts.json / macros 等
       <程序目录>\logs\   native.log
   从 0.4.33 及更早版本升级时，旧 %APPDATA% 里的配置会**自动搬过来**一次，原文件保留。


二、首次使用（按顺序）
   0. 双击「一键安装.cmd」—— 一次做完下面 1/2/3 三步并自动复检（会请求管理员权限）
   1. 双击 IPRC1000-Native.exe
   2. 打开「环境与安装」页，看 5 项检查：
        √ 虚拟声卡 VB-CABLE        已安装
        √ CABLE Input（播放端）     存在
        √ CABLE Output（录音端）    存在
        √ 默认录音设备 = CABLE Output  已设置
        √ 虚拟键盘驱动 WinUHid       就绪
      哪项是 ×，就点下面「一键处理」里对应的按钮。
   3. 打开豆包输入法，把「麦克风」选成 CABLE Output
   4. 按一下遥控器任意键，界面右上角应变成「● 遥控器在线」

      ★ 右上角现在有**三种**状态，分别代表不同的故障层次（0.4.37 起）：
         ● 遥控器在线            = 真的收到按键了，可以正常用
         ◐ 已连接，按键通道未就绪 = 蓝牙通着，但一个按键都没收到
                                   （最常见：遥控器休眠；或曾被改造成 raw ⇒ 用 --restore-keyboard 恢复）
         ○ 遥控器休眠            = 连蓝牙事件都没有（按任意键唤醒）

      现场排查按键问题，先跑这一条命令（只读，不改任何设置）：
         IPRC1000-Native.exe --hid-probe
      ★ 0.4.41 起它会列出**全部** Raw Input 设备名，并逐台标注认领结果：
         [VID/PID 精确匹配] / [蓝牙HID兜底] = 已认领，按键通道通
         [未认领] = 设备名没对上规则 ⇒ 把这份清单发回来即可精确适配
         列表为空   = 遥控器休眠/蓝牙断链（先按一下唤醒），或名字读取失败
      ★ 0.4.40 起按键走 Raw Input（WM_INPUT），不再打开 \kbd 接口：
        该接口 ACL 是 SYSTEM-only，管理员也打不开（旧版日志的 err=5 就是它）。
        按键本身**不需要管理员**；语音的 ETW 会话才需要。
      ★ 临时验证「是不是设备名没认上」：
        设环境变量 IPRC1000_RAWINPUT_ANY=1 后重跑主程序，若按键立刻生效
        ⇒ 就是过滤规则问题（此时物理键盘也会触发动作，验证完请取消该变量）。

      ★ 0.4.43 起支持音频调试录音（默认关闭，零开销）：
        在「环境与安装」页勾选「录音调试」即可，不用设环境变量。
        文件写到**程序目录下的 wav\\**（capture-16k-*.wav / capture-48k-*.wav）：
          capture-16k-*.wav   收到的原始音频（16 kHz）
          capture-48k-*.wav   重采样后真正送进 CABLE 的（48 kHz）
        判读：16k 正常、48k 变调 ⇒ 重采样坏了；
              两个都小/糊/断续       ⇒ 接收或解码坏了；
              两个都正常却没声音     ⇒ CABLE 环节（设备没打开/声道错）。
        录音是边写边回写 WAV 长度的，任何时候强杀进程，文件都能直接播。


三、按键映射
   · 上方「配置组」可切换：默认配置组 / 鼠标模式
   · 每行点「改键」→ 弹窗里选键盘按键（或文本 / 宏）
   · 语音键是**全局固定**的，由「输入法」页决定，不能被单个组改掉


四、输入法
   · 豆包 = 右 Alt（默认）
   · 微信输入法 = Ctrl + Win（需把系统默认输入法也切成微信）
   · 触发方式：按住说话 / 点按一次（再按一次结束）
   · 语音的松手时机（v0.4.8 起）：
        - 你松开语音键的瞬间就结束（约几毫秒）；
        - 如果松手的信号没传到（链路抖动），**最多再等 3 秒**自动结束，不会卡住；
        - 说完话停顿超过 3 秒，会被当作"说完了"。想继续说，别停超过 3 秒。


五、宏
   · + 新建宏 → 右侧「名字」框可改，「循环」可设次数（0 = 一直循环）
   · + 按键：按一下要录的键 → 选 按下+弹起 / 只按下 / 只弹起 → 设按住时长 → 插入
   · + 延迟：插一步「等待 N ms」（插完可直接在列表里改数字）
   · 左键 / 右键 / 中键：点一下就在**当前鼠标位置**插一次点击
   · 点某一步可选中它，之后插入的操作会插到那一步**下面**
   · F10 开始录制 / F11 结束录制（也可用界面按钮）
   · 每一步右侧的 × 删除该步


六、托盘
   · 右下角图标右键：打开界面 / 开机自启 / 安装虚拟声卡 / 安装驱动 / 退出
   · 关闭窗口 = 收进托盘（不退出），要退出请用托盘菜单


七、日志（以及诊断命令）

   --hid-probe    按键链路诊断（列 Raw Input 设备 + 匹配遥控器的设备名，不打开 \kbd）
   --restore-keyboard  把误改造的遥控器恢复成键盘模式（需管理员；之后按键唤醒或重启蓝牙适配器）
   --check-key    查某个键绑了什么    例：--check-key 08
   --diag         模块/线程/内存概况
   --repair       等价于界面「一键修复」
   <程序目录>\logs\native.log
   所有诊断信息都在这里（按键、注入、宏、录制、安装）。


八、已知限制
   · **不要改造遥控器**。保持键盘模式才有 HID 接口、才收得到按键；
     代价是系统会同时往焦点窗口打字母。改造会让接口消失、按键与语音全断，
     为保住可用性，当前不做吞键（后续版本再解决双触发）。
   · 按键走 Raw Input，不需要管理员；语音的 ETW 会话、声卡/驱动/注册表安装
     需要管理员。非管理员时界面顶部会如实提示，不会自动弹 UAC。
   · 只含 usage 0x0C 的快照会被当"心跳"丢弃；Raw Input 实测 VKey I 反查正是
     0x0C。已单独计数并写日志，待真机逐键确认（已绑定 23 键不含 0x0C，暂不影响）。
   · 语音长句受**遥控器固件**限制：约 30 秒会自动收工（不是本程序截断的）。
   · 遥控器底部指示灯 **绿色 = 蓝牙链路没建立/断开**，红灯 = 正常语音。
     绿灯时按键会完全没反应（不是程序坏了）：把遥控器靠近电脑再按一下；
     反复出现请检查蓝牙适配器的"允许计算机关闭此设备以节约电源"是否开着。
   · 录制键盘用轮询（8 ms），极快的连续按键可能漏；严格顺序敏感的组合键
     建议用「+ 按键」弹框逐条加。
   · 截图点击（模板匹配）尚未实现，绑了也不会动作。
