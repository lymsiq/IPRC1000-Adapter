# 开发机 × 客户机 同步协议 v1

> 目的：让"开发改代码"和"真机验证"两条线用**同一份证据、同一套判据、同一个结论**，
> 不再出现两边各说各话、结论互相推翻的情况。
> 落点：`Z:\vibe\iprc1000_native\`（客户机挂载开发机共享，双方读写同一份）

---

## 0. 为什么要有这个协议

2026-11-06 这一轮排查中，双方对**同一个故障**给出过互相矛盾的判断，全部源于工具和判据不统一：

| 分歧点 | 开发侧说法 | 客户侧说法 | 实际（用同一解析器复核） | 原因 |
|---|---|---|---|---|
| 断开原因码 | `reason=0x01` | `reason=0x01` | **`0x13` REMOTE_USER_TERMINATED** | 两边解析器同一个 off-by-one，`b[3]` 应为 `b[5]` |
| 假绿灯来源 | `Enum\HID` 有残留节点 | — | **本机 `Enum\HID` 无任何 A5C 残留** | 开发侧按开发机推断，未在客户机实测 |
| 遥控器 BD_ADDR | — | 打印成 `0C:20:C0:47:F3:13` | **`20:C0:47:F3:13:D6`** | 同样 `b[3:9]` 应为 `b[2:8]` |

三次偏差、一个根因：**各写各的解析器、各读各的注册表**。
所以协议的第一条不是流程，是**工具唯一化**。

---

## 1. 三条硬规则

**R1 — 唯一证据源**
任何结论必须引用证据包内的 `文件名 + 具体字段值`。禁止"我这边看是……"这类无路径陈述。
不能附路径的结论一律视为未验证。

**R2 — 唯一判据**
HID 是否绑定，**只认两个值**：

```
① HKLM\SYSTEM\CurrentControlSet\Enum\BTHENUM\{00001124-0000-1000-8000-00805F9B34FB}_*  存在，且 Service = HidBth
② <配对记录>\ServicesFor<主机MAC> 下的「缓存 SDP 服务记录」条数 > 0
```

**不允许**用 `Enum\HID` 下有 `HID_DEVICE_SYSTEM_KEYBOARD` 当判据 —— 那是历史残留，会骗人。
（本轮实测：客户机 `Enum\HID` 干净，程序却仍报"键盘模式正确"，说明现有 `remote_still_keyboard()` 的判据必须换掉。）

**R3 — 唯一解析器**
`tools\parse_hci.py` 是 HCI/L2CAP 的唯一解码器。谁改它，谁在本台账登记版本号；
另一边**不许**再用私有脚本出结论。私有脚本可以写，但结论必须能被 `parse_hci.py` 复现。

## 3. 每轮交接固定三段

任何一方向另一方交付，必须写满这三段，缺一段打回：

```markdown
### 改了什么
src\hid_reader.rs:120-180  —— 把 CreateFileW(\kbd) 改成 RegisterRawInputDevices
行为差异：不再产生 hidMiss，改为 WM_INPUT 收包

### 依据什么
handoff\20261106-round1\03-cap.txt 第 5-8 行
  L2CAP ConnReq PSM=HID-Control SCID=0x0040 ident=0x02
  L2CAP ConnRsp ... >> REFUSED_PSM
=> 主机侧无 PSM 0x0011 监听者

### 怎么验
命令：tools\diag-bt.ps1
期望：C2 输出 `[OK] Service = HidBth 已绑定`，C3 输出 `缓存 SDP 服务记录: N 条`（N>0）
判定：两条同时满足 = PASS
```

## 4. 状态机（每条记录必须带状态）

| 状态 | 含义 | 进入条件 |
|---|---|---|
| `S0` | 未复现 | 只有现象描述 |
| `S1` | 已定位到层（射频/L2CAP/SDP/HID/注入/UI） | 有 ETW 或注册表证据 |
| `S2` | 根因确认 | 有"反证"——即能解释为什么另一台机器正常 |
| `S3` | 已修待验 | 有代码 diff 或操作步骤 |
| `S4` | 验证通过 | 7 步判定链全 PASS + 连续 3 次冷启动可复现 |

**晋升必须带证据，不接受口头。**

---

## 5. 分工边界

| 谁 | 能做什么 | 不能做什么 |
|---|---|---|
| 开发侧 | 改 `src\*.rs`、构建、WinUHid 注入、打包 | 不写"自动修复设备绑定"的功能；不改客户机注册表 |
| 测试侧（客户机） | 跑真机、抓 ETW、出 diag 包、复现步骤 | 不改代码、不替开发"猜"修法 |

**明确禁止的历史坑**：`convert_to_hid_compliant()` 这类自动把设备改成 `HID-compliant device` 的"一键修复"，
会把 `kbdhid` 摘掉、按键彻底死。此功能必须删除或默认关闭，且不得由 UI 按钮触发。

## 6. 双机对照是硬要求

任何**涉及 HID 绑定/驱动栈**的结论，必须在两台机器各跑一次并对比：

| 机器 | 蓝牙 | 定位 |
|---|---|---|
| 开发机 `192.168.8.186` | Intel AX200 | 已知正常，对照组 |
| 客户机 `PC-20260728LQXO` | Realtek 8821CE（USB VID_0BDA&PID_C821） | 故障机 |

产出 `07-diff.md`：只写"值不同"的行，不写一致的项。
**差异项才是结论，一致项只是背景。**

## 8. 修复验收的 7 步判定链

全部 PASS 才算修好，任一 FAIL 就停在那一步，不要往下猜：

| # | 检查 | 期望 |
|---|---|---|
| 1 | `Enum\BTHENUM\{00001124-...}` 节点 | 存在 |
| 2 | 该节点 `Service` | `HidBth` |
| 3 | 缓存 SDP 服务记录 | 条数 > 0，含 HID(0x1124) |
| 4 | 遥控器连上时 `HidBth` 事件 2 | **不再出现** |
| 5 | ETW `L2CAP ConnRsp` 结果 | `SUCCESS`（不再是 `REFUSED_PSM`） |
| 6 | ETW 出现 `PSM=0x0013 HID-Interrupt` | 有且有数据包 |
| 7 | `bridge-stats.json` | `hidReports>0`、`keyEvents>0`，Raw Input 列表出现设备 |

第 5 步是关键分水岭 —— `REFUSED_PSM` 变 `SUCCESS` 说明 HidBth 真的接管了。
