# 发版前自测清单（开发机必过）

> 起因：2026-11-06 一下午发了 6 个版本（0.4.43 → 0.4.48），每个都是改完就打包。
> 结果客户机连装三个版本，问题一个没解决，还多出"录音 0 字节""安装日志说按④可读"两个新 bug。
>
> **规则：下面 8 项在开发机全过，才允许打 tag 发版。**

---

## 0. 前置：开发机自身必须是好的

这一条以前被跳过，导致"自测"从来无从谈起。

```powershell
IPRC1000-Native.exe --doctor D:\doctor-dev.txt
```

必须看到：

```
[2] HID 服务节点   OK
[3] HID 服务绑定   OK    Service = HidBth
[4] HID 子节点     OK    0 个 = Fail；非键盘 = OK（提示，可放行）
```

`[4]` 是 **0 个** 时先修设备（休眠/节点被删）；**非键盘是提示，不需要修**：

| `[4]` 显示 | 做什么 |
|---|---|
| 0 个 | 按遥控器任意键唤醒；仍无则删设备重配对 |
| 有但"非键盘" | 提示项：按键/语音照常，无需处理；仅当需要 Raw Input 时用 `--restore-keyboard` |

**修不好就不要往下测** —— 在一台坏的机器上测出来的"通过"没有意义。

---

## 1. 编译与静态检查

```powershell
cargo test --release
cargo check --release     # 必须 0 警告
```

## 2. 按键能收到（ETW ACL 主路径 / Raw Input 备用）

启动程序 → 按遥控器 4 个方向键 + OK。

```powershell
# 看 stats
type "$env:APPDATA\IPRC1000 Adapter\bridge-stats.json"
```

- `keyEvents` 增加（每按一次 +2：DOWN + UP）
- `hidMiss` **停止增长**
- `firstKeyUsage` 变成非 `0x00`

**不通就不要测后面**：按键是最基础的，它不通语音也没意义。

## 3. 按键能注入

焦点放在记事本 → 按 OK 键 → 应该出现换行（或你配的动作）。

- `keyEvents` 增长但记事本没反应 ⇒ **注入层**问题（查 `[INJ]` 日志）
- 记事本出现 `i` / `m` ⇒ 字符泄漏，属**已知**（见 §8.3），不算失败但要在发版说明里写

## 4. 语音能收到音频

按住语音键 3 秒说话，松手。

- `samples16` 增速应 ≈ **16000/秒**（3 秒 ≈ 48000）
- `sessions` +1
- `seqLost` 不应超过总帧数的 5%

## 5. 录音文件非 0

```powershell
dir D:\IPRC1000-Native\wav
```

- 两个文件都应 > 44 字节（44 是空 WAV 头）
- **0 字节 = 头没落盘**（0.4.48 修过一次，别再回归）

## 6. 音频真的送到 CABLE

- `native.log` 里 `原生音频输出：CABLE Input (…)` **不能是 16 Ch**
- 输入法麦克风选 `CABLE Output`，说一句应该出字

## 7. 退出干净

托盘右键 → 退出 → 任务管理器确认进程没了 → 重新启动 → 仍能按键。

- 不应出现 `interface version < 1`
- 不应出现 `VHF\...IPRC1000ADAPTERKEYBOARD` 的 Unknown 节点

## 8. 界面不骗人

打开「环境与安装」页，逐条看：

- 每一条的状态与 `--doctor` **一致**
- 没有"改绑 ⇒ 接口消失 / 按键全断 / 必须恢复键盘模式 / 必须重配对"这类与事实相反的文案
- 失败项都带**怎么修**
