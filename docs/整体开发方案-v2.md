> 2026-11-06　｜　取代 v1

## 0. 结论摘要

| 项 | 结论 |
|---|---|
| 语言 | **Rust**（不换 C#） |
| UI | **egui**（不换 WPF/WebView2） |
| 注入 | **SendInput 主** + WinUHid 可选（与 v1 相反，见 §8.1） |
| 按键 | **Raw Input 主** + ETW 辅 |
| 音频 | ETW 解 ACL 帧 + 自带 VB-CABLE |
| 配置 | **六层继承**，TOML，`%ProgramData%` / `%LocalAppData%` 分存 |
| 部署 | 三层分离（程序包 / 机器档案 / 用户迁移包）+ 七步向导 + 四命令 |
| 首要任务 | **不是加功能，是让换机不需要调试** |

**一句话**：把"已经验证的内核"固定下来，把"随机器变化的部分"全部外置为可检测、可配置、可迁移的部署层。

## 1. 为什么不换 C# / 不换 WPF

外部方案建议 `C# + .NET 10 + WPF`，架构思想完全正确，但**前提判断有误**：它以为现网是 GitHub 上那个 WinForms + WebView2 的旧仓库，实际上生产版本是 **Rust 原生 v0.4.46**。

换语言意味着重写这些**每一行都对应过真实故障**的代码：

| 模块 | 行数 | 踩过的坑 |
|---|---|---|
| ETW ACL 帧解码 + 抖动缓冲 | ~800 | CID 动态分配、分片切法不固定、起播自适应 |
| 语音租约 | ~150 | 三条实测依据、`reconcile` 是唯一写入口 |
| Raw Input 认领 + 报告快照 | ~600 | `\kbd` ACL、`HELD[256]` 还原、空报文语义 |
| 注入（WinUHid / SendInput） | ~300 | 整份报告快照、孤儿回收 |
| 音频重采样 + 端点匹配 | ~500 | 16k→48k 三倍速、`CABLE In 16 Ch` 选错 |

**约 2350 行"踩过才知道"的逻辑**，重写没有并行收益——复杂的是 Windows 底层行为，不是语言。

| | Rust（现） | C# WPF self-contained | C# framework-dependent |
|---|---|---|---|
| 安装包 | **5.7 MB** | 60–80 MB | 3 MB + 需装 .NET 10 |
| 启动 | **50 ms** | ~300 ms | ~250 ms |
| 内存 | **120 MB** | ~150 MB | ~150 MB |

客户机已经要装 WinUHid 驱动 + VB-CABLE，**再要求 .NET 运行时是第三个变量**。

**但架构全收**：它的 11 个项目 = 我们的 11 个 crate，一对一映射。

## 3. 配置体系：六层继承

```
① program   内置默认，随 exe 编译，只读
② model     遥控器型号（IPRC1000.toml）—— 按键表、usage、HID 特征
③ system    Windows 10 / 11 差异 —— 功能可用性、已知缺陷
④ machine   %ProgramData% —— 适配器、音频端点、驱动状态、设备实例
⑤ user      %LocalAppData%\<SID> —— 映射、输入法、触发模式、偏好
⑥ app       前台应用覆盖（只存覆盖项，回退 ⑤）
```

**低层提供默认，高层可覆盖；未设置继续继承。**

### 3.1 目录

```
%ProgramData%\IPRC1000\
  device-models\IPRC1000.toml
  system-profiles\Windows10.toml  Windows11.toml
  machines\machine-<id>.toml          ← 本机生成，不跨机复制
  drivers\

%LOCALAPPDATA%\IPRC1000\<SID>\
  settings.toml                        ← 用户偏好、触发模式
  profiles\windows-default.toml  office.toml
  input-methods\doubao.toml  wechat.toml
  app-profiles\chrome.toml  vlc.toml
  backups\                             ← 每次保存前一份 .bak
  logs\  wav\
```

**机器级的东西一律不进用户目录**，用户级的东西一律不进 ProgramData —— 这条保证"换机只搬用户目录"。

### 3.2 机器档案（本机生成，绝不跨机复制）

```toml
schema_version = 1
machine_id     = "generated-local-id"

[platform]
os      = "Windows11"
build   = "22631"
arch    = "x64"

[remote]
model          = "IPRC1000"
instance_id    = "HID\{00001124…}_VID&00020a5c_PID&8502\8&…"
container_id   = "…"
bound          = true

[event_source]
provider        = "BthPort"
available       = true
decoder_version = "1"

[injector]
backend          = "sendinput"     # ★ 不是 winuhid
winuhid_available = false

[audio]
virtual_device   = "VB-Audio Virtual Cable"
endpoint_id      = "…"             # 本机绑定，换机必须重解析
selected_name    = "CABLE Input"
verified         = true
```

**绝对不能写进这个文件的**：租约到期时间、`held[]`、当前按键状态、上次配对密钥。

### 3.3 用户配置（唯一要迁移的）

```toml
schema_version = 1
user_profile_id = "default"

[voice]
input_method = "doubao"
trigger_mode = "hold"              # hold | toggle
[voice.lease]
pause_ms    = 3000                 # 允许覆盖，但有上下限校验
no_voice_ms = 10000

active_profile = "windows-default"
preferences = { start_with_windows = true, start_minimized = true }
```

**`pause_ms` 校验范围 1000–8000，超出拒绝并记日志** —— 不允许"为了适配某台机器"把它调到 20 秒。

### 3.4 设备型号（`IPRC1000.toml`，随包发布）

```toml
schema_version = 1
model = "IPRC1000"
label = "IPRC1000 遥控器"

[match]
tlc       = "0x01/0x06"            # 准入：键盘集合
prefer    = ["vid:0A5C", "pid:8502", "name~IPRC"]

[[keys]]
id            = "voice"
usage         = "0x10"
label         = "语音"
produces_char = true               # ★ 决定要不要抑制连发/吞字符
voice_key     = true

[[keys]]
id            = "up"
usage         = "0x52"
label         = "上"
produces_char = false              # 方向键不打字符，不需要处理
```

**`produces_char` 是新增字段**，它把"哪些键需要处理字符泄漏"从代码搬进配置。

## 4. 关键数据结构

### 4.1 语音事件（解耦的唯一接口）

```rust
pub enum VoiceEvidence {
    KeyDown,          // 0x10 首次按下
    AudioFrame,       // 每帧音频（唯一续租源）
    EmptyPacket,      // 真松手
    DeviceLost,       // 断链
    AppExit,          // 进程退出
}
```

租约核心**只认这五个**。换机器只换事件源，租约一行不动。

### 4.2 对账观测（三态）

```rust
pub enum KeyObservation { Down, Up, Unknown }
```

**`GetAsyncKeyState` 返回 0 ≠ Up** —— 锁屏、切换用户、UAC 安全桌面下采样会失败。此时：

- 返回 `Unknown`
- **`reconcile_voice` 遇到 `Unknown` 不做任何补发**，只记录
- 连续 N 次 `Unknown` 才降级为"不参与对账"（避免在安全桌面上疯狂补发）

### 4.3 动作

```toml
[bindings.ok]
tap        = { type = "key", vk = "VK_RETURN" }
double_tap = { type = "key", vk = "VK_APPS" }
long_press = { type = "macro", id = "menu" }

[bindings.menu]
tap = { type = "chord", keys = ["VK_CONTROL", "VK_O"] }
```

支持：`key` / `chord` / `sequence` / `media` / `text` / `macro` / `voice` / `profile_switch` / `none`。

### 4.4 输入法

```toml
[input_methods.doubao]
label = "豆包输入法"
detect_reg = "HKCU\\Software\\ByteDance\\DoubaoIME"

[input_methods.doubao.push_to_talk]
strategy = "hold"
keys = ["RALT"]

[input_methods.doubao.toggle]
strategy = "latched_hold"        # 豆包只有长按：第一次 DOWN 后保持，第二次 UP
keys = ["RALT"]

[input_methods.wechat]
label = "微信输入法"

[input_methods.wechat.push_to_talk]
strategy = "hold"
keys = ["LCTRL", "LWIN"]

[input_methods.wechat.toggle]
strategy = "native_toggle"       # 微信有独立切换键时优先
keys = ["LCTRL", "LWIN", "LSHIFT"]
compat_verified = false          # 待实测，未验证前界面标"实验性"
```

`strategy` 值：`hold` / `latched_hold` / `native_toggle`。**三种都要实现**，否则"点按"在某些输入法上必然失效。

## 5. 部署与环境管理

### 5.1 三层分离

| 层 | 内容 | 是否跨机 |
|---|---|---|
| **程序包** | exe、驱动、默认配置、向导 | 通用，只构建一次 |
| **机器档案** | 适配器、端点、驱动、实例 ID | **每机生成，不复制** |
| **用户包** | 映射、输入法、偏好、计时覆盖 | **导出/导入** |

### 5.2 首次部署向导（七步）

| 步 | 动作 | 用户参与 |
|---|---|---|
| 1 | 系统环境：版本、架构、蓝牙、管理员、ETW 能力 | 自动 |
| 2 | 运行环境：WinUHid（可选）、VB-CABLE、驱动绑定 | 自动，缺什么装什么 |
| 3 | 绑定遥控器：发现 → 识别型号 → 确认 | 确认 |
| 4 | 音频链路：发现端点 → 解一帧 ACL → 试播 200 ms | 自动 |
| 5 | 选择输入法：检测豆包/微信 → 选触发模式 → **真实快捷键测试** | 确认 |
| 6 | 恢复配置：导入用户包 | 一键 |
| 7 | 完整自检：租约、释放、断链、重连、输入法 | 自动 |

**原则**：不能只查"文件存在"，要查**驱动实际加载、设备确实绑定、事件真正到达**。

### 5.3 四个命令入口

```
IPRC1000-Native.exe --doctor                    环境体检（每项给：探到的值/判据/怎么修）
IPRC1000-Native.exe --repair                    修复当前机器环境
IPRC1000-Native.exe --export-profile out.zip    导出用户配置
IPRC1000-Native.exe --import-profile in.zip     导入用户配置
```

**`--doctor` 的输出必须三列**：

```
[音频端点]  选中 "CABLE Input"       判据：名字含 CABLE 且不含 "16 CH"
            当前候选：CABLE Input | CABLE In 16 Ch | VB-Audio Virtual Cable
            若不对：设置 → 声音 → 输出，或改 machine.toml 的 audio.selected_name
```

**只说"未就绪"不算合格**——今天大部分时间浪费在"程序说了结论但没说依据"上。

## 8. 硬结论（2026-11-06 实测固化，不许再犯）

### 8.1 注入：SendInput 主，WinUHid 可选

WinUHid 是 UMDF 虚拟 HID，三层结构性不稳：全局单槽位、异常退出留幻影节点、`interface version < 1`。今天所有"按键完全不注入"都来自它失败后 `set_fatal`。

**改成**：SendInput 为默认；WinUHid 装了才用；**任何失败都不 fatal，只记日志并降级**。

### 8.2 键盘 TLC 被 RIM 独占

`0x01/0x06` 的 HID 设备由 Raw Input Manager **独占打开**，任何应用（含管理员）都读不到——这是防键盘记录器的内核设计。**今天 60 次 `err=5` 的真正原因**。

推论：
- 改绑成 HID-compliant device 也读不到（TLC 未变）
- 官方解法是固件加 vendor-defined TLC（`0xFF00`），我们改不了
- **"不打字符"只能靠钩子或驱动**，没有第三条路

### 8.3 字符泄漏是物理后果

遥控器 usage `0x0C` = I、`0x10` = M，按键会打进焦点窗口，且 Windows 自动重复会让按住时连发。

| 方案 | 效果 |
|---|---|
| 接受 | 按住语音键打出 `mmmmmm` |
| 首次 DOWN 后立即 `SendInput(KEYUP)` | 压到 **1 个** m |
| 钩子只吞 `VK_M` / `VK_I`（150 ms 窗口） | **0 个** |

**优先级 P5 专项**，默认实现"压到 1 个"，钩子作为可选项。

### 8.4 删掉所有破坏配对的操作

- 「④ 禁止打字符」——**移除**（改绑后 Raw Input 消失，必须重配对才能恢复）
- `fix-pairing` 类脚本——**不进程序**
- 「⑤ 恢复键盘模式」——只在检测到改绑残留时提示

**配对记录是用户资产，程序任何时候都不删。**

### 8.5 `LastConnected` 不可靠

它的值只在**配对时**更新，之后重连不刷新。**不能用来判"此刻是否在线"**。

判在线只看：`HID 子节点 Status == OK` 且 `bridge-stats.keyEvents` 在增长。

### 8.6 CABLE 端点必须按分数选

同机可能同时存在 `CABLE Input` 与 `CABLE In 16 Ch`。**写错端点表现为"有波形、没声音"**。

打分：精确 `CABLE INPUT` 且不含 `16 CH` > 其它非 16Ch > 16Ch 变体。

### 8.7 采样率必须显式对齐

上游 16 kHz（320 样本/20 ms），CABLE 输出 48 kHz。直接写 = **3 倍速、音调变尖、识别不出字**。必须 3:1 上采样。

### 8.8 录音不许在热路径做 I/O

`push_payload` 跑在 ETW 回调线程，且持 `Bridge` 锁。同步写文件会堵回调 → 丢事件。必须 `try_send` + 后台线程 + 定期回写长度。

### 8.9 界面判据不能骗人

今天出现过：

```
环境检查：「已改绑 ⇒ 按键可读」   ← 假的
状态栏：「按键通道未就绪」        ← 真的
```

**任何判据必须能回答"凭什么这么说"**。`--doctor` 的三列输出是强制要求。

### 8.10 静默失败必须留痕

`Rec::open` 原来用 `.ok()?`，配置是 `true` 也看不到任何提示，查了半天。**所有"降级/跳过/失败"都要有一行日志，带实际值。**

### 8.11 编码与脚本

- `.ps1` 必须 **UTF-8 with BOM**（5.1 按 ANSI 读会把中文注释里的引号搞乱，整份脚本语法崩）
- `.cmd` 用 GBK
- 正则里 `'^USB\'` 这类尾部反斜杠是转义符，**永远匹配不上**——用 `-like 'USB*'`

---

### 8.12 启动顺序、健康状态与会话收尾

> 来源：GitHub 同类项目调研（SayAll 的生命周期管理、Voice VibeCoding 的串行自检）
> 今天所有"不知道哪坏了"的困惑，都源于这三件事没做。

#### ① 串行启动，不并发

`Bridge::new` 现在同时开 cable、WinUHid、ETW、Raw Input —— 谁失败谁先报，互相掩盖。改成严格串行，**每步产出状态，失败降级不退出**：

```
1. 读配置（六层合并）
2. 音频：选端点 → 开流 → 试播 200 ms ──▶ Ok / Degraded / Failed
3. 注入：SendInput（恒可用）→ WinUHid（可选）──▶ Ok / Degraded
4. 输入：Raw Input 注册 → 认领 → ETW 会话 ──▶ Ok / Degraded
5. 就绪
```

```rust
pub enum Health {
    Ok(String),        // 带"实测到的值"
    Degraded(String),  // 能用但有妥协
    Failed(String),    // 不能用，但主链路继续
}
```

**降级矩阵**（任何一条失败都不许让整个程序停摆）：

| 失败项 | 降级后仍可用的能力 |
|---|---|
| 音频（CABLE 打不开） | 按键全部可用 |
| WinUHid | 用 SendInput 注入 |
| ETW 会话 | 按键走 Raw Input |
| Raw Input 注册 | 按键走 ETW |
| **全部失败** | 界面可用，`--doctor` 能说明原因 |

#### ② 三个健康状态，别挤成一个

今天界面只有一句「按键通道未就绪」，分不清是蓝牙断了、驱动没装还是端点选错。拆成三个独立指示灯，**每个都要能回答"凭什么"**：

| 灯 | 绿 | 黄 | 红 |
|---|---|---|---|
| **蓝牙链路** | HID 子节点 `Status=OK` **且** 近 60 s 内有 `keyEvents` | 状态在 OK/Unknown 间抖动 | 无 HID 子节点 |
| **按键注入** | 最近一次注入 `[INJ] ... ok` | 回退到 SendInput | 两种都失败 |
| **音频通路** | 端点名匹配成功 **且** `frames` 在增长 | 打开成功但零帧 | 端点未匹配 |

**判据必须可复核**：界面上每一项都要能展开看到"实测值 / 判据 / 不符合时怎么修"——和 `--doctor` 同一套输出，不要两套。

#### ③ 断链后主动重建，不要等

`bridge-stats` 里有 `gapNoEvents`（断流期间零事件）。今天出现过 `maxGapMs = 11569` —— **等了 11.6 秒它自己都没恢复**。

规则：

```
gapNoEvents > 0 且持续 ≥ 3 s
  → 停 ETW 会话 → 重新开
  → 重新 RegisterRawInputDevices
  → 记一行 [恢复] 重建消费者（原因：连续 N 秒无事件）
```

重建要**限频**（60 s 内最多 3 次），否则链路真断时会变成忙等。

#### ④ 动设备之前，先关自己的会话

任何会"改设备状态"的操作（退出、安装、卸载、`--repair`、配对修复）之前，必须按顺序：

```
1. CloseTrace         停 ETW 会话
2. RIDEV_REMOVE       注销 Raw Input
3. 释放全部注入键       （RAlt / 修饰键）
```

**今天 `fix-pairing` 就是在会话还活着的时候硬删注册表**——句柄没释放，删了又回来，白折腾半小时。

顺序不能反：**先关消费者，再动设备**。

## 9. 风险与对策

| 风险 | 概率 | 影响 | 对策 |
|---|---|---|---|
| 改设备识别后认不到遥控器 | 高 | 按键全无 | 规则表 + 旧匹配 fallback；`--doctor` 明确报"未匹配" |
| 拆 `backend.rs` 拆丢续租点 | 中 | 语音卡键 | 租约整块搬，不注释不改条件 |
| 配置迁移丢用户键位 | 中 | 投诉 | 迁移前 `.bak`，迁移后逐字段比对日志 |
| 输入法快捷键随版本失效 | 高 | 语音不能用 | 全外部化 + `compat_verified` 标记 + 界面标"实验性" |
| 多用户配置串 | 中 | 互相覆盖 | 按 SID 隔离；Session 0 只做硬件 |
| Program Files 只读 | 中 | 启动崩 | 配置一律写 `%APPDATA%`/`%ProgramData%` |
| 字符泄漏 | 高 | 体验差 | P5 专项，见 §8.3 |
| 钩子导致全键失灵 | 低 | 灾难 | 只碰 2 个键 + 150ms 窗口 + 后台过期清理 + 可关 |

## 10. 验收标准

### 10.1 单机（对齐协议 A–G）

### 10.2 换机（14 项）

## 11. 附录

### 11.1 从 MoteDeck 抄什么

**抄**：手势三动作（只对配了双击的键延迟）、按前台应用切档案（只存覆盖项）、整体配置导出导入。

**不抄**：它的按键读取（`kbd` ACL 挡住）、语音采集（我们走私有 ACL 帧）、Python/174 MB、GPL-3.0 代码。

详见 v1 附录 §10。

### 11.2 与两份外部方案的差异

| 项 | 外部方案 | v2 |
|---|---|---|
| 语言 | C# + .NET 10 + WPF | **Rust + egui**（核心 2350 行已验证，不重写） |
| 注入优先级 | WinUHid 优先 | **SendInput 优先**（§8.1） |
| ETW 实现 | 考虑改 C# | **保持 Rust**（协议级算法，换语言无收益） |
| 多用户 | 第一版就做服务 + Named Pipe | **P2 再做**，架构预留 `ports` 边界 |
| 字符泄漏 | 两份都没提 | **单列 §8.3 + 验收项** |

**采纳自外部方案**：11 模块拆分、六层配置继承、`%ProgramData%`/`%LocalAppData%` 分存、Session 0 只做硬件、`VoiceEvidence` 解耦、`KeyObservation` 三态、四命令入口、换机验收表。
