## 1. 测试目的与范围

### 1.1 目的

验证**一条完整链路**在真机上可用，而不是验证某一个组件"看起来正常"：

```
遥控器按键
  → 蓝牙链路（ACL 建立 / 链接密钥可用）
  → BTHENUM 服务节点（{00001124} HID-Control，Service=HidBth）
  → HID 子节点（kbdhid 键盘集合）
  → Raw Input 认领（VID_0A5C & PID_8502 精确匹配）
  → usage 解析 + 键表映射
  → WinUHid 虚拟键盘注入（或 UDP 转发到主程序）
```

链路任意一环缺失，都会表现为"按了没反应"，但**修法完全不同**。本协议的目的是让每一次"没反应"都能定位到唯一环，不允许跳过层级直接下结论。

### 1.2 在范围内

- 链路层、枚举层、认领层、按键层、注入层、语音层的功能验收
- 异常恢复路径（断开、休眠、进程异常退出、槽位残留）
- 回归最小集（每次改版必跑）

### 1.3 不在范围内（已知边界，不判失败）

见 §7。特别是：**遥控器按键会在焦点窗口打出字母（含语音键的 `M`）** —— 这是"保持键盘身份"的必然代价，不在本轮验收范围，按 §7.1 单独跟踪。

## 2. 判定总则

### 2.1 三条硬规则（沿用同步协议 v1）

**R1 唯一证据源**：任何"通过/不通过"必须附 `文件名 + 字段值`。禁止"我这边看着正常"这类无路径陈述，不能附路径的一律视为未验证。

**R2 唯一判据**：HID 是否绑定，只认这两个值，**不允许**用 `Enum\HID` 下有无 `HID_DEVICE_SYSTEM_KEYBOARD` 当判据（历史残留会骗人）：

```powershell
# ① 服务节点存在且 Service=HidBth
Get-PnpDevice | ? InstanceId -match 'BTHENUM\\\{00001124-0000-1000-8000-00805F9B34FB' |
  % { $s=(Get-PnpDeviceProperty -InstanceId $_.InstanceId -KeyName DEVPKEY_Device_Service).Data; "$($_.Status) svc=[$s]" }

# ② SDP 缓存记录条数 > 0
$k='HKLM:\SYSTEM\CurrentControlSet\Services\BTHPORT\Parameters\Devices\20c047f313d6'
(Get-ChildItem $k -Recurse | ? PSChildName -like 'CachedServices*') | % { $_.PSChildName; (Get-ChildItem $_.PSPath).Count }
```

**R3 唯一解析器**：HCI/L2CAP 解码只用 `tools\parse_hci.py`。私有脚本可以写，但结论必须能被它复现。

### 2.2 通过门槛

| 等级 | 要求 |
|---|---|
| **准入门禁** | §3 环境基线 6 项**全部**满足，否则本轮测试作废，先修基线 |
| **P0 通过** | P0 用例 **100%** 通过，不允许"基本能用" |
| **P1 通过** | P1 用例通过率 ≥ 90%，未通过项须有书面豁免 |
| **P2** | 记录即可，不作为放行条件 |

### 2.3 一票否决项（出现任一项，本轮直接判不通过）

1. `BTHENUM\{00001124}` 节点消失（说明又被改了驱动绑定）
2. 测试期间执行过「④ 禁止打字母」或「一键修复」
3. 用任务管理器强杀进程后未重启就继续测（WinUHid 槽位会残留）
4. 证据包缺少 `bridge-stats.json` 或 `native.log`

## 3. 测试环境基线（前置条件）

开测前逐项打勾，任何一项 `✗` 就地停下修，不允许"边测边修"。

| # | 检查项 | 通过标准 | 采集命令 |
|---|---|---|---|
| B1 | 遥控器配对记录 | `Parameters\Devices\20c047f313d6` 存在，含 `ServicesFor*` ≥1 个 | 见 §2.1② |
| B2 | HID 服务节点 | `BTHENUM\{00001124-…}` 存在，`Status=OK`，`Service=HidBth`，`ProblemCode=0` | §2.1① |
| B3 | HID 子节点绑定 | `Enum\HID\{00001124-…}_VID&00020a5c_PID&8502` 存在，`Service=kbdhid`（**不允许为空**） | `Get-PnpDeviceProperty` 见下 |
| B4 | SDP 缓存 | `CachedServices` 记录数 ≥1 | §2.1② |
| B5 | 适配器节能 | `EnhancedPowerManagementEnabled=0`、`SelectiveSuspendEnabled=0` | `HKLM:\SYSTEM\CurrentControlSet\Enum\USB\VID_0BDA&PID_C821\00E04C000001\Device Parameters` |
| B6 | WinUHid 槽位 | 无 `VHF\...IPRC1000ADAPTERKEYBOARD` 的 `Unknown`（幻影）节点 | `Get-PnpDevice \| ? InstanceId -match 'VHF\|WINUHID'` |

### 3.1 B3 的正确查法（**不要按实例号**）

```powershell
Get-PnpDevice -EA SilentlyContinue | ? InstanceId -match '00020A5C' | % {
  $s=(Get-PnpDeviceProperty -InstanceId $_.InstanceId -KeyName DEVPKEY_Device_Service -EA SilentlyContinue).Data
  "{0,-8} svc=[{1}] {2}" -f $_.Status,$s,$_.InstanceId
}
```

判读要点：

| 现象 | 含义 | 处置 |
|---|---|---|
| `svc=[kbdhid]` | 键盘身份正确 | ✅ 继续 |
| `svc=[]`（空）+ 类 GUID `{745a17a0…}` | 被改绑成 `HID-compliant device / input.inf` 空壳 | ❌ 执行 §9.2 恢复 |
| `Status=Unknown` | 遥控器休眠，节点变 phantom，**正常** | ✅ 不算故障 |
| 实例号 `&3&0000` / `&4&0000` 变化 | 每次重新配对会变 | ✅ 匹配必须用 VID/PID，**禁止用实例号** |

### 3.2 基线快照（双方必须同一份脚本）

```powershell
& powershell -NoProfile -ExecutionPolicy Bypass -File 'Z:\vibe\iprc1000_native\tools\snapshot.ps1'
```

归档为 `handoff\<日期>-roundN\snapshot-<主机名>.txt`。`20261106-round3` 的对拍结论是：**客户机已处于目标态，开发机被改绑过**，开发机需先点 ⑤ 恢复 `kbdhid` 再参与对拍，否则基线永远是错的。

## 4. 测试用例

### A 组 · 链路层

| 编号 | 优先级 | 用例 | 步骤 | 预期 | 证据 |
|---|---|---|---|---|---|
| A01 | P0 | 遥控器能连上本机 | 按任意键唤醒，等 3 s | `LastConnected` 时间被刷新到当前时刻（±1 min） | `BTHPORT\...\20c047f313d6` 的 `LastConnected` |
| A02 | P0 | 无"超出范围"风暴 | 连续按键 10 s，观察系统日志 | `HidBth Id=2` 事件出现 ≤1 次 | `Get-WinEvent -ProviderName HidBth` |
| A03 | P1 | 设备名可读 | 读父节点名称 | 包含 `Broadcom Bluetooth Wireless` | `DEVPKEY_Device_DeviceDesc` |
| A04 | P2 | 链接密钥可存 | 重启后检查 | `BTHUSB Id=18`（存不了密钥）允许出现，**不影响本轮判定** | 系统日志 |

### B 组 · 枚举与认领层

| 编号 | 优先级 | 用例 | 步骤 | 预期 | 证据 |
|---|---|---|---|---|---|
| B01 | P0 | 服务节点齐全 | 读 `BTHENUM` 下 0A5C 全部节点 | 至少 `{00001000}`、`{00001124}`、`{00001200}` 三个，`{00001124}` 为 `HidBth` | PnP 枚举输出 |
| B02 | P0 | HID 子节点绑定正确 | 唤醒后查 B3 | `svc=kbdhid`，`ProblemCode=0` | §3.1 命令 |
| B03 | P0 | Raw Input 认领成功 | 唤醒后等 5 s | 日志出现 `[HID] 已认领` 且 `bridge-stats.hidOpen ≥ 1`；`hidMiss` **停止增长** | `native.log`、`bridge-stats.json` |
| B04 | P1 | 未认领时可自证 | 遥控器休眠时看日志 | 每 15 轮输出一次设备清单，`枚举 N 个` 的 N 稳定 | `native.log` |

## 7. 已知边界（不判失败）

### 7.1 出字母 / 出 `M`

`src\report.rs:27` → `pub const VOICE: u8 = 0x10;`。HID 键盘 usage `0x10` 即字母 **M**（Mic 首字母），描述符如此，改不了。因为**保持键盘身份是"能收到按键"的前提**，这半个 `M` 是必然代价。

预期方案（未实施）：低级钩子 `WH_KEYBOARD_LL` + "遥控器活跃 1.5 s 窗口"吞键 + 首键 `Backspace` 补偿。测试时**只记录现象，不判失败**。

### 7.2 其他

| 边界 | 说明 |
|---|---|
| 遥控器休眠时 `Status=Unknown` | phantom 节点，正常，不是故障 |
| `BTHUSB Id=18`（存不了链接密钥） | 8821CE 等组合卡休眠后密钥丢失 ⇒ ACL 层无包 ⇒ 按键语音全断；软件无法修复，禁用其蓝牙换 AX200/AX210 |
| 首键延迟 | 休眠唤醒首键可能慢 1~2 s，只要不丢即可 |
| 物理键盘被误吞（未来方案下） | 遥控器活跃窗口内的同键会被吞，概率极低 |
| `snapshot.ps1` 的 `cable_present` | 按名字含 `CABLE` 就判绿，口径与程序不同，**以 `native.log` 为准** |
| 实例号变化 | 每次重配对 `&3&0000` → `&4&0000`，必须以 VID/PID 匹配 |

## 9. 应急与回滚

### 9.1 **禁止操作清单**（做了就要重新配对，别再试）

| ❌ 禁止 | 原因 |
|---|---|
| 界面「④ 禁止打字母」 | 改绑成 `HID-compliant device / input.inf`，`hidOpen` 恒 0，按键与语音全断（11:00 与 15:14 两次实测证死） |
| 界面「一键修复」 | 内部仍走改绑逻辑，等同于上一条 |
| 手动删 `BTHENUM\{00001124}` 节点 | 会进入"枚举孤儿态"：配对在、服务缓存空，SDP 不会自动重跑 |
| `--restore-keyboard` | 节点不存在时无事可做；节点存在时也不重建服务，对孤儿态无效 |
| 任务管理器强杀进程 | 留下 `VHF\...IPRC1000ADAPTERKEYBOARD` 幻影，占 WinUHid 槽位 |

### 9.2 恢复键盘模式（只删 HID 子节点，不动服务节点）

```powershell
$h = (Get-PnpDevice | ? InstanceId -match 'Enum\HID|HID\\\{00001124' | ? InstanceId -match '00020A5C').InstanceId
pnputil /remove-device "$h"
# 然后按遥控器唤醒，PnP 会从 HidBth 父节点重新长出 svc=kbdhid 的子节点
```

删完**必须**验证三个服务节点还在：

```powershell
Get-PnpDevice | ? InstanceId -match '00020A5C' | % {
  $s=(Get-PnpDeviceProperty -InstanceId $_.InstanceId -KeyName DEVPKEY_Device_Service).Data
  "{0,-8} svc=[{1}] {2}" -f $_.Status,$s,($_.InstanceId -replace '\\[78]&.*','')
}
```

### 9.3 孤儿态（节点彻底消失）的唯一解：完整重新配对

顺序不能换：

1. **遥控器断电复位**（抠电池 10 s / 长按电源 10 s）—— 固件里可能残留 PENDING 的 HID-Control 通道
2. **关掉另一台主机的蓝牙**或把遥控器拿远 —— BCM20734 只维系一条链路
3. GUI 删除设备（设置 → 蓝牙和其他设备 → 删除）
4. 重启适配器，确认 `Enum\BTHENUM` 与 `Enum\HID` 无 0A5C 残留
5. 遥控器进配对模式 → 添加设备 → **配对全程持续按键**（SDP 只在这几秒内跑，一睡就超时）

成功判据：`{00001124}` 出现 + `CachedServices` >0 + HID 子节点 `svc=kbdhid`。
