## 1. 这是什么

把 **Verizon FiOS IPTV 遥控器（型号 IPRC1000）** 当作 PC 的**可编程输入设备**：

- **按键**：遥控器的 23 个键 → 任意键盘按键 / 组合键 / 宏 / 文本 / **启动一个程序**
- **语音**：遥控器麦克风 → 虚拟声卡 → 豆包或微信输入法（不说话时完全不占 CPU）
- **零 WebView**：不依赖 WebView2/浏览器，界面自绘

### 1.1 它到底是什么设备（别买错、别写错）

| 项      | 事实                                                                                |
| ------ | --------------------------------------------------------------------------------- |
| 正式名称   | **Verizon FiOS IPTV Bluetooth Remote**（美国 Verizon 电视盒 IPSTB1200 的配件）              |
| 型号     | **IPRC1000**（主板丝印 IPRC1000；外壳背面左下 `RC3602301/02BR` + 蓝牙 MAC）                      |
| 芯片方案   | 博通 **BCM20734**（Bluetooth Smart 双模 + 红外，单芯片）                                      |
| 连接     | **蓝牙 + 红外双模**；本项目只用蓝牙                                                             |
| 供电     | **4 节 7 号(AAA) 电池，必须 4 节都装上**（红外 2 节 + 蓝牙 2 节，缺一不可）                               |
| 麦克风    | 机身顶部**双面拾音**麦（这就是语音功能的来源）                                                         |
| 重量     | 约 89.3 g                                                                          |
| USB 识别 | `VID_0A5C` / `PID_8502`（0A5C = 博通；这也是为什么 Linux 侧要放 `Vendor_0a5c_Product_8502.kl`） |

**配对 / 复位（硬件操作）**

- 首次配对：长按右上角 **PWR**，等方形指示灯**蓝灯闪烁** → 在 Windows 蓝牙里添加设备。
- 恢复配对状态：**同时按「上一频道(last)」+「下方向键」**，即可回到可配对状态。

> 采购提示：市面同名"IPTV 遥控器"很多，认 **IPRC1000 / BCM20734 / Verizon FiOS** 三个关键词，  
> 否则按键表与语音链路都对不上（本项*目的 23 键表就是按这只遥控的丝印做的）。*

## *2. 两个发行版（同一套配置，按机器选）*

|               | *完整版*                                                               | *Win32 版*                     |

*两个版本****共用****&#x20;`<应用目录>\data\` 下的同一份配置，换版本不用重配。*

## 4. 安装步骤

### 4.1 完整版（推荐走安装器）

1. 运行 `IPRC1000_Native_Setup_v<ver>.exe`（或解压 zip 后右键**以管理员身份运行** `一键安装.cmd`）。
2. 安装器会依次：装虚拟声卡 → 装虚拟键盘驱动 → 设默认麦克风 → **检查遥控器按键通道状态**（只判状态，不改造）。
3. 启动 `IPRC1000-Native.exe`，进入「环境与安装」页确认四项全绿。
4. 若某项显示 ⚠，点「一键修复」——缺什么补什么，可能弹 UAC。

### 4.2 Win32 版（解压即用）

1. 解压到任意目录（建议 `D:\IPRC1000-Win32`，**不要**只把 exe 单独拿出来——  
   同目录的 `WinUHid.dll`、`assets\` 是运行必需）。
2. 双击 `IPRC1000.exe`。
3. 顶部状态条应显示 `声卡 ✓ 麦克风 ✓ 键盘驱动 ✓ 遥控器 ✓`；  
   有 ⚠ 就点「一键修复」。

### 4.3 首次必做：保持「键盘」模式，不要改造

2026-11-06 真机结论：**改造与"能收到按键"不可兼得**。把 HID 节点改绑成  
`input.inf / raw` 后，Windows 不再注册该设备的 HID 接口（节点 `present=True`  
却枚举不到任何遥控器接口），`hid_reader` 无从打开、中断通道也不建立 ⇒  
按键与语音同时全断、4 秒超时重连。

| 状态              | 判据                        | 该做什么                                                                  |
| --------------- | ------------------------- | --------------------------------------------------------------------- |
| 仍是键盘（**正确**）    | 环境页「遥控器按键通道」绿             | 不用动。按键可读；系统会同时打字母，属已知边界                                               |
| 已改绑 raw（**故障**） | 环境页红 + `--hid-probe` 匹配 0 | 运行 `IPRC1000-Native.exe --restore-keyboard`，或点环境页「④ 恢复键盘模式」，再按一下遥控器唤醒 |
| 未连接             | 检测不到 HID 节点               | 按一下遥控器唤醒 / 重新配对                                                       |

旧版（≤0.4.39）的安装器与文档会引导改造；**已按旧说明改造过的机器必须先恢复**。  
`--restore-keyboard` 会删除旧 devnode，让 PnP 重新枚举时装回 `keyboard.inf/kbdhid`（需管理员）。

> ⚠ 删节点后 Windows **不会在蓝牙链路未断时自动重建子节点**。恢复完必须二选一：  
> ① 按一下遥控器唤醒 / 重新配对；② 禁用再启用蓝牙适配器强制枚举：
>
> ```powershell
> $id='USB\VID_0BDA&PID_C821\00E04C000001'   # 按实际 InstanceId 改
> Disable-PnpDevice -InstanceId $id -Confirm:$false
> Start-Sleep 3
> Enable-PnpDevice -InstanceId $id -Confirm:$false
> ```
>
> 判据：设备管理器出现 `HID Keyboard Device / svc=kbdhid`，不再是 `svc=[]` 空壳。

## 6. 常用操作

### 6.1 把某个键改成"打开程序"

**完整版**：「按键映射」页 → 目标行点「**程序**」→ 选 exe → 该键即变为启动键。  
显示为 `打开 微信`。

**Win32 版**：选中一行 → 顶部「**绑定程序**」→ 选 exe。

**命令行装配**（远程/批量）：

```bat
IPRC1000-Native.exe --bind-program favorite "D:\Program Files\Tencent\WeChat\WeChat.exe"
```

### 6.2 查某个键到底绑了什么

```bat
IPRC1000-Native.exe --check-key 08
```

输出示例：

```
usage   = 0x08
id      = favorite   name = ♡ 收藏
绑定串  = "-2002"
action  = Some(-2002)   （后端「打开程序」读的就是这个）
vks     = []
=> 按下会执行：打开 WorkBuddy
```

判读：

- `action` 为 `None` 且绑定串是负数 → 动作没落到运行时（旧版本 bug，v0.4.31 已修）
- `绑定串` 为空、`vks` 为空 → 该键未绑定（会按出厂默认）

### 6.3 测试某个快捷方式

```bat
IPRC1000-Native.exe --launch-shortcut 2
```

## 8.5 按键链路：五层排障表

按键从遥控器到应用要过五层，**断在哪一层，症状完全不同**，别一上来就重装驱动。

| 层 | 判据 | 怎么看 | 断了的症状 |
|---|---|---|---|
| ① 蓝牙链路 | 父节点 `BTHENUM\DEV_<MAC>` Present=True | 设备管理器 | 4.25 s 监督超时断开重连、完全无反应 |
| ② 蓝牙驱动栈 | L2CAP `PSM 0x0013` HID-Interrupt 建立 | ETW `BTH-BTHPORT` EventID 402 | 微软通用 `bth.inf` 缺厂商 filter 时中断通道**从不发起**（客户机 SENKE 已装 Realtek `oem24.inf` 修复，属机器侧） |
| ③ Raw Input 设备 | `--hid-probe` 里带 `[VID/PID 精确匹配]` / `[蓝牙HID兜底]` 的设备 > 0 | 命令行 | `[HID] 暂未认领遥控器 Raw Input 设备` 反复出现；启动日志会列出**全部真实设备名** |
| ④ 注册与投递 | 日志 `[HID] Raw Input 已注册` + `[HID] ✓ 已认领遥控器 Raw Input 设备` | `native.log` | 注册失败 → 收不到 `WM_INPUT`；名字没认上 → `[HID] WM_INPUT 已到达但未认领` 并打印 VKey/设备名 |
| ⑤ 映射注入 | `native.log` 出现 `[KEY]`；`keyEvents` 增长 | 看日志 | 有 `REPORTS` 无 `[KEY]` = VKey 未映射（日志给 `未映射 VKey=0x..`）或键位没绑（`--check-key`） |

> **按键通道已换成 Raw Input（0.4.40）**：不再 `CreateFileW` 打开 `\kbd`。
> 键盘顶层集合接口 ACL 是 SYSTEM-only，非 SYSTEM 进程必然 `err=5`，管理员也无效；
> Raw Input 走 `WM_INPUT` 窗口消息，不碰句柄，绕开该限制且不需要管理员。
> 判据看 `REPORTS` 与 `[HID] Raw Input 已注册`，不再看"打开成功几次"。
> 旧日志里的 `打开失败 err=5（累计 1044 次）` 正是这条老路径的证据。

> **0.4.41：认领失败必须留痕**（客户机日志复盘，2026-11-06）。0.4.40 只按
> `0A5C+8502` 过滤设备名，客户机日志出现「`Raw Input 已注册` 之后『暂未发现设备』
> 连刷 60 轮、却看不到任何设备名」。那轮唯一能用的按键其实来自 **ETW 旧通道**——
> `bridge.log` 的 `[RAW] len=6` 是 `acl[8..14]` 固定 6 字节格式，而 Raw Input 的
> 快照是变长（`len=1` 按下 / `len=0` 松开），说明 Raw Input 一条都没贡献。
> 三处修复：① `RIDI_DEVICENAME` 改固定 512 WCHAR 缓冲，规避 `pcbSize` 字节/字符语义坑；
> ② 加蓝牙 HID 服务 GUID 兜底认领（仅在没有 VID/PID 精确匹配时生效，避免误认蓝牙物理键盘）；
> ③ 启动/巡检打印真实设备名，`WM_INPUT` 到达却没认领时打印 VKey + 名字。
> 现场一键判定：设 `IPRC1000_RAWINPUT_ANY=1` 重跑，按键生效 ⇒ 纯过滤规则问题。

> **界面右上角的三态**（0.4.37 起）分别对应不同层：  
> · `● 遥控器在线` = 30 秒内真的收到过按键（第 ④ 层通了）  
> · `◐ 已连接，按键通道未就绪` = 链路在动但一个按键都没收到（第 ②③④ 层之一断了）  
> · `○ 遥控器休眠` = 连链路事件都没有（第 ① 层）
>
> 早期版本只有"在线/休眠"两态，判据是"30 秒内有没有任意蓝牙事件"——  
> 信令保活就能把它刷绿，于是"显示在线、按键全无"这类故障被藏住。

### 8.5.1 为什么绝对不能改造遥控器

0.4.36 当时的理解是「raw 绑定缺一个消费者，补上 `hid_reader` 即可」——  
**这个结论已被 2026-11-06 真机复测推翻**：

```text
11:00:47  HID 节点 present=True / Status=OK / CM_PROB_NONE   ← 设备在
          全系统 HID 接口 9 个，匹配遥控器 0 个                ← 但接口根本没注册
```

raw 绑定（无 TLC 的 HID 集合）不注册 `GUID_DEVINTERFACE_HID`，所以：

- `hid_reader` 的 `CreateFile` 永远无从打开（`hidOpen` 恒 0、`hidMiss` 持续涨）；
- Windows 不建 HID 中断通道（PSM 0x0013）⇒ 遥控器 4 秒监督超时断开重连；
- ETW 只剩链路信令（`otherEvents` 涨、`keyEvents` 恒 0），音频一并失效。

**结论：保持键盘模式。** 此时 `kbdhid` 与本程序都能拿到按键（Raw Input 走窗口消息，
不需要共享打开句柄），代价是系统也会打字母（已知边界，见 §10）。
已经改造的用 `--restore-keyboard` 恢复。

### 8.5.2 另一半根因：`\kbd` 接口的 ACL 是 SYSTEM-only

客户机 SENKE SYDT-L-311-B 的实测（`F:\IPRC1000-按键链路修复方案-交接开发.md` §3）：

```text
\\?\hid#{00001124-...}_vid&00020a5c_pid&8502#...#{4d1e55b2-...}\kbd
[HID] 打开失败 err=5（累计 1044 次）
```

`err=5` = `ERROR_ACCESS_DENIED`。Windows 自 Vista 起对**键盘/鼠标 HID 顶层集合**
加了保护性 ACL，只允许 SYSTEM 打开；**管理员身份同样无效**。
这不是驱动或权限配置问题，提权、改共享模式都解决不了，只有换成 Raw Input。

因此 0.4.40 起 `hid_reader` 完全不打开设备句柄：独立线程注册
`RIDEV_INPUTSINK` 的隐藏窗口，按设备名（含 `0A5C` + `8502`）过滤 `WM_INPUT`，
用 `HELD[256]` 还原成 HID 报告快照交给 `report::diff()`。
Python 原型在客户机实测 20/20 按键全捕获、按下/抬起完整、零丢失、不需要管理员。

> 这也是「开发机正常 / 客户机不能用」的主要诱因之一：客户按旧说明第一步就把  
> 唯一可用的按键通道改掉了，而旧安装器仍报「安装完成」。见 `docs/开发机-客户机差异架构审计.md`。

## 10. 已知边界（不承诺的能力）

| 项          | 说明                                 |
| ---------- | ---------------------------------- |
| 语音首包延迟     | **300–500 ms**，来自遥控器固件，软件侧无法消除     |
| 键注入延迟      | 15–20 ms                           |
| 媒体键（音量/静音） | 受虚拟 HID 报告描述符限制（仅键盘页），可能无效         |
| 语音键改键      | 不支持，由输入法决定（全局语义，刻意设计）              |
| 遥控器打字母     | 不改造（键盘模式）是按键通道成立的前提；当前不做吞键，属已知边界   |
| usage `0x0C` 歧义 | `report::GHOST` 把只含 `0x0C` 的快照当心跳丢弃；Raw Input 实测 `VKey 0x49`(I) 反查正是 `0x0C`。已单独计数 `GHOST_SNAPSHOTS` 并写日志，**待真机逐键确认**是否放宽。已绑定 23 键不含 `0x0C`，暂不影响功能 |
| 多实例        | 不支持（两个实例会互相停掉彼此的 ETW 会话）           |
| 宏播放中按遥控器   | 任意键 = 停止播放（防跑飞）                    |
| 无显卡驱动      | 完整版会降级到 Win32 界面；长期使用建议直接用 Win32 包 |
