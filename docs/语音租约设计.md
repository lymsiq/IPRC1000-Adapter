# 语音键「租约」模型 · 设计与实测

> 版本：v0.4.46 起有效（模型自 v0.4.8 引入，此后未变）
> 代码：`src/backend.rs:154-170`（模型定义）、`1712-1760`（实现）
> 历史：`.workbuddy/memory/2026-10-31.md:73-109`（当晚设计 + 34/34 实测）
> 适用范围：`IPRC1000-Native.exe` 的语音键（usage `0x10`，即键盘的字母 M）

---

## 1. 一句话

```
右 Alt 应该按住  ⟺  now_ms() < VOICE_LEASE_MS      （一个 AtomicU64）
```

没有状态机，没有"开始/结束"两个状态。只有一个到期时间戳：**没续租就必然过期**。

---

## 2. 为什么不用状态机

语音键的"结束"**没有可靠事件源**。三条都是真机实测：

| 观测 | 数据 | 后果 |
|---|---|---|
| 按住期间遥控器**零报文** | 抓包 156 条 / 52 次按键 | 无法靠"没报文"判松手——按住时本来就没报文 |
| 固件 30 秒自动收工**不发**松开报文 | 20:59:19.5 → 20:59:29.8 无任何 `[RAW]` | 长按到固件收工，永远等不到结束事件 |
| 断链则彻底没有事件 | 蓝牙超时后 `[RAW]` 直接消失 | 断链时也判不出"结束" |

所以任何"判断结束"的代码**只能猜**。每猜错一次就是一个 bug —— 历史上判据①②③④ 全是这么长出来的：

- 判据①：`RESUME_MS` 内没恢复就认为松手 → 长句被切
- 判据②：音频停 3 s 认为结束 → 停顿长的句子被切断
- 判据③：看门狗盯 `0x10` → 误杀
- 判据④：会话静默判结束 → 与②互相打架

**租约把"猜"换成"过期"**：不续租就自动到期，**卡键在数学上不可能发生**。

---

## 3. 写入只有四处，读取只有一个

| 事件 | 动作 | 到期时间 |
|---|---|---|
| `0x10` DOWN（按下） | `voice_arm(T_NOVOICE_MS)` | now + **10 s**（等用户开口的窗口） |
| 每帧音频到达 | 续租 `T_PAUSE_MS` | now + **3 s** |
| **空报文**（真松手） | `voice_disarm()` | 0（立即放） |
| 断链 / 退出 / 解卡键 | `voice_disarm()` | 0（立即放） |

**读取**只有一个地方：`reconcile_voice()`。

```rust
// backend.rs:1720
pub fn voice_arm(&mut self, ms: u64) {
    VOICE_LEASE_MS.store(voice::arm(now_ms(), ms), Ordering::Relaxed);
    self.reconcile_voice("arm");
}
pub fn voice_disarm(&mut self, why: &str) {
    VOICE_LEASE_MS.store(voice::disarm(now_ms()), Ordering::Relaxed);
    self.reconcile_voice(why);
}
```

---

## 4. 两条不可退让的不变量

**① `held[0x10]` 只能由 `reconcile_voice()` 修改。**

任何其它代码直接改 `held[0x10]` 都是 bug —— 因为那会绕过租约，制造出"系统按着但租约已过期"的分裂状态。

**② 可靠事件才能续租，不可靠事件只能收口。**

- 能**续租**的只有：`0x10` DOWN（明确的按下事件）、每帧音频（明确的"还在说"证据）
- 只能**收口**（disarm）的：空报文、断链、退出

这条铁律的收益：**松开报文丢了，最坏多按一个 `T_PAUSE`（3 秒），绝不会卡键**。
反过来如果把"音频停了"当续租依据，就会在用户暂停时误判。

---

## 5. 对账：每 500 ms 一次自愈

即使在租约模型下，注入侧也可能与预期不符（驱动吞键、焦点切换等）。所以每 500 ms 一次：

```rust
// backend.rs:1734
fn reconcile_voice(&mut self, why: &str) {
    let want = now_ms() < VOICE_LEASE_MS.load(Ordering::Relaxed);
    let actual = unsafe { GetAsyncKeyState(VK_RMENU) } < 0;
    if want != actual { 补发一份整份报告 }
}
```

- 租约说"该按着"、系统说"没按" → **补发**
- 租约说"该放开"、系统说"还按着" → **补发松开**
- 日志：`[语音] ★对账：租约说按着，系统说没按 ⇒ 补发一份报告`

正常运行中**不应该看到这行**。看到就说明注入链路有问题，值得查。

## 7. 唯一需要按体感调的旋钮

```rust
const T_PAUSE_MS: u64 = 3_000;   // 说话停顿容忍
const T_NOVOICE_MS: u64 = 10_000; // 按下后等开口的窗口
```

| 调小 `T_PAUSE_MS` | 调大 `T_PAUSE_MS` |
|---|---|
| 停顿稍长就切句，但松手后放开更快 | 句子更完整，但松手后右 Alt 多按一会儿 |

`T_NOVOICE_MS` 一般不用动：它只影响"按下但一直不说话"时多久自动放开。

## 9. 排障速查

| 现象 | 先看 | 判读 |
|---|---|---|
| 语音键按了不生效 | `native.log` 有没有 `[语音 ...] DOWN 按下` | 没有 ⇒ 按键没到，查 Raw Input/ETW |
| 说完话右 Alt 一直按着 | 有没有 `租约到期 ⇒ 放开右Alt` | 没有 ⇒ `reconcile_voice` 没跑（线程挂了？） |
| 说话被切成多段 | `T_PAUSE_MS` 是否被改小；看 `[语音] 租约到期（原因=` | 原因若是 `pause` 而非 `松手`，说明是超时兜底 |
| 频繁出现 `★对账` | 注入链路（WinUHid 句柄/驱动） | 对账是自愈机制，频繁触发说明主路径有问题 |
| 松手后多按几秒 | 遥控器是否发了空报文 | 不发（固件收工）⇒ 正常，靠 `T_PAUSE` 兜底 |

日志格式（自带时间戳）：

```
[语音 14:36:10.397] DOWN 按下（in_session=false 模式=按住）
[语音 14:36:10.397] 租约续上 ⇒ 按住右Alt（arm）
[语音 14:36:19.490] 收口 ⇒ 放开右Alt（松手（空报文），had_audio=true）
```

分析脚本：`F:\vibe\_soak\voice_report.py <offset>`（用已知答案校准过）。

## 10. 与 C# 版的关系

C# 版（`IPRC1000-Adapter`）走的是**状态机 + 多重判据**，历史上有"语音键卡住"的长期问题（`stuck-guard.log` 就是为它写的）。

原生版改用租约后，`stuck-guard` 整套逻辑不再需要 —— 这里**不是为了简化而简化，是因为"结束"根本无法被可靠观测**。

如果将来要把 C# 版也改过来，核心是同一句：**不要找"结束事件"，去找"能证明还在继续的事件"**（这里是音频帧）。
