## 0. 结论先行

**不是「客户机缺某个运行库」，是四类结构性缺陷叠加。** 其中两条与机器无关、在任何新装机上必现；两条是开发机隐含状态造成的。

| 类 | 根因 | 性质 |
|---|---|---|
| **A 权限模型错配** | 主程序 / Setup / 两个 exe 的 manifest 全是 `asInvoker`；只有 `一键安装.cmd` 提权且**只跑一次 `--install`**。常驻业务线程的 ETW `StartTrace` 需要管理员 | 开发机 Administrator 账户天然全绿；标准用户客户机必然全断 |
| **B 交付物与源码分叉** | `package.py` 从开发机 `D:\IPRC1000-Native\assets` 拷资源，不是 `ROOT/assets`；Win32 包原样拷了 Native 的安装脚本 | **与机器无关，必现**：Native/Setup 装出来就缺正确脚本；Win32 首次安装入口直接断 |
| **C 设备改造链路自相矛盾** | 11-06 真机结论已写进 `device_probe.rs:481-500`「改造与能收到按键不可兼得」，但 `commands.rs:378`、`hid_reader.rs:175`、使用说明、SOP、`一键安装.cmd` 仍引导客户去改造 | **唯一会主动把可用机器改坏的动作**，且是文档第一步 |
| **D 隐含状态 + 假绿灯 + 不可观测** | BthPort 三个 ETW 注册表值全仓无写入代码；状态判据多处判"文件/注册表/退出码"而非"设备真实状态"；注入失败降级到空 UDP | 开发机早已被 C# 版改好并重启；客户机全新 → 音频帧 100% 判截断 |

**最短全功能不可用链（标准用户客户机，必现）**

```
双击 exe（asInvoker，非管理员）
  └→ backend.rs:3163 StartTrace 失败 → eprintln! + return  ← 业务线程静默退出，UI/托盘照常
       ├→ 音频帧 0 → voice 租约拿不到唯一续租点(backend.rs:2287) → 10s 后放开右 Alt → 语音全断
       └→ --install 里 pnputil / 证书 / newdev 全部失败 → Injector::open 6 次重试耗尽
            └→ 按键改发 UDP 127.0.0.1:31681，原生内核无接收端，且 cmd() 结果被丢弃(backend.rs:2067)
                 → 按键全断、零日志
界面：egui 三态显示「按键通道未就绪」/ Win32 状态条「键盘驱动 ✓」；Setup 仍显示「✓ 安装完成」
```

**第二条（文档诱导的破坏链，同等致命）**

```
客户按 使用说明.txt:7-10 / SOP §4.3「首次必做改造」
  → commands.rs:378 convert_remote() → device_probe.rs:304 convert_to_hid_compliant()（input.inf raw）
  → raw 绑定不注册 HID 设备接口（device_probe.rs:493-495 真机实测）
  → hid_reader 枚举匹配 0、无消费者；Windows 不建 HID 中断通道 → 4s 超时重连
  → 按键 + 音频全无、ETW 只剩信令（界面仍"在线"）
```
代码里给的「正解：不改造 + 钩子吞键」**目前没有吞键实现**——全仓只有 `recorder.rs` 的录制钩子，且明确不吞键。即：不改造 = 打字母双触发，改造 = 收不到按键，两难。

| `<exe> --install 2>&1 \| tee install.txt` | 退出码 0；2=需重启；3=有手动项 | 3 ⇒ 看哪一项 `manual`（大概率"默认麦克风"或"遥控器改造"） |
| `<exe> --restore-keyboard 2>&1 \| more` | 已删 N 个旧节点 | **改造后按键全无时的回退命令，文档里没写** |
| 日志 | `<应用目录>\logs\native.log` / `bridge.log` / `bridge-stats.json` | 装在只读目录才回退 `%APPDATA%\IPRC1000 Adapter\...`；**别按 Win32 包 README 找** |
| `data\native.json` 的 `logEnabled` | `true` | 为 false 时历史日志已被 `purge_logs()` 删除，不可恢复 |

**判读 `bridge-stats.json`**：`hidOpen>0` 且 `hidDirect` 随按键增长 = HID 通道通；`hidMiss` 持续涨且 `hidOpen=0` = 没醒/已改造/VID 不匹配；`truncatedFirst>0` = MaxEtwBytes 未生效；`frames=0` + `otherEvents` 涨 = 只有 L2CAP 信令，音频解析没进来。

**取证打包**：`data\*.json` + `logs\*.log*` + `install-*.log` + `%TEMP%\iprc-setup.log` + `--hid-probe` / `--audio` / `--install` 三条输出。**不要点 Win32 的「导出配置」**（路径是错的）。
