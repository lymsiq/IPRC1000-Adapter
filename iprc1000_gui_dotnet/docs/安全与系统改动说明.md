# 安全与系统改动说明（买家问答 / 自证清白用）

> 2026-10-17 审计。**结论先行**：程序不出网、不上传、不注入别的进程；  
> 但它**确实会装一个自签名内核驱动**、**装一个全局键盘钩子**、**改三处蓝牙 ETW 注册表**、  
> **装一个虚拟声卡**。这四件事是杀软/反作弊误报的主要来源，必须如实告诉买家。  
> 本文分两部分：① 系统改动清单 ② 杀软/反作弊风险评估与应对。



---

## 一、对系统的全部改动

### 1. 注册表（需要管理员）

| 位置                                                          | 写入内容                                                              | 为什么                                                     |
| ----------------------------------------------------------- | ----------------------------------------------------------------- | ------------------------------------------------------- |
| `HKLM\SYSTEM\CurrentControlSet\Services\BthPort\Parameters` | `EtwDropLargeEvents=0`、`EtwLogSensitiveData=1`、`MaxEtwBytes=8192` | 让蓝牙栈把 657 字节的音频帧完整写进 ETW。不改这三项，音频帧会被丢弃/截断，**语音功能直接不工作** |
| `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`        | 一个启动项（**可选**，用户点"开机自启"才写）                                         | 让程序随系统启动                                                |

> ⚠ `EtwLogSensitiveData` 这个名字看着吓人，实际含义是"把负载内容也写进 ETW"——  
> 我们正是要靠它拿到音频数据。它只影响**本机 ETW 会话**，不对外发送任何东西。  
> 卸载/恢复：把这三个值删掉即可（程序内可一键恢复）。

### 2. 内核驱动（两个，都需要管理员 + UAC）

| 驱动                    | 来源                             | 作用                                          | 签名                                                     |
| --------------------- | ------------------------------ | ------------------------------------------- | ------------------------------------------------------ |
| **WinUHidDriver.sys** | 包内自带（`assets/winuhid/driver/`） | 创建一个**虚拟 HID 键盘**，按键注入走它（SendInput 会被输入法忽略） | **自签名**（安装时把 `WinUHidPublisher.cer` 加进本机"受信任的根证书颁发机构"） |
| **VB-CABLE**          | 第三方（VB-Audio，官网下载/包内打包）        | 虚拟声卡，把遥控器麦克风接到系统默认录音设备                      | 正规商业签名                                                 |

安装方式：`pnputil /add-driver` + 注册根设备节点 + Bind，装完可能出现"需重启"。

### 3. 钩子（回答"有没有钩子"：**有**）

- **全局低层键盘钩子 `WH_KEYBOARD_LL`**（`SetWindowsHookExW(..., 0)` = 全局）。
- **它能看到系统里所有进程的按键**——这是"键盘记录器"的典型特征，杀软启发式会盯这个。  
  程序的用途只是：认出哪些键是遥控器发来的，然后把它们**吞掉**（`return 1`，不往下传），  
  再以我们想要的形式重新注入；非遥控器键一律 `CallNextHookEx` 放行并原样传递。
- 同时装了 **Raw Input**（用于识别设备、维护按住集合）。
- ⚠ 在"设备已切成非键盘"的正常模式下，按键来源走 **ETW**，钩子仍在但基本只做观察；  
  只有设备退回键盘模式时才会真正吞键。**两种模式都装钩子，因为启动时不知道设备处在哪种模式。**

### 4. 网络

| 项    | 实际情况                                                                                   |
| ---- | -------------------------------------------------------------------------------------- |
| 对外监听 | **无**。只绑 `127.0.0.1:31680`（音频）和 `127.0.0.1:31681`（按键），纯回环                              |
| 出网   | **无遥测、无上传、无统计**。唯一一次"联网"是用户点「去官网下载 VB-CABLE」时用浏览器打开 `vb-audio.com`                     |
| 界面   | WebView2 加载 `https://iprc1000.local/index.html` —— 这是**本地虚拟域名**（映射到包内 `ui/` 文件），不是真互联网 |

### 5. 文件与进程

| 项        | 位置                                                                                                           |
| -------- | ------------------------------------------------------------------------------------------------------------ |
| 配置与日志    | `%APPDATA%\IPRC1000 Adapter\`（`keymap.json` / `mouse.json` / `audio.json` / 各种 `.log` / `bridge-stats.json`） |
| 临时文件     | `%TEMP%\IPRC1000Adapter\vb-cable-stage\`（解压 VBCABLE 安装包）                                                     |
| 桌面       | 仅当用户点「导出 WinUHid 到桌面」时，创建 `桌面\IPRC1000 WinUHid 手动安装\`                                                        |
| 进程       | `IPRC1000 Adapter.exe`（界面）+ `etw_consumer.exe`（Rust 语音桥，读 BthPort ETW）                                       |
| **不做什么** | **不注入其他进程、不 DLL 注入、不建远程线程、不读剪贴板、不截屏、不开后门**                                                                   |

## 二、杀软 / 反误报评估

### 会被注意到的（按风险排序）

| # | 项                 | 误报风险   | 原因                                  | 缓解                                                    |
| - | ----------------- | ------ | ----------------------------------- | ----------------------------------------------------- |
| 1 | **自签名内核驱动**       | **中高** | 反作弊会校验驱动签名链；自签名 + 创建虚拟 HID 设备是常见误报点 | 代码开源可查；仅在需要"输入法不过滤"时才装；卸载脚本在包里                        |
| 2 | **全局 LL 键盘钩子**    | **中**  | 杀软启发式里的经典"键盘记录器"行为                  | 钩子只认遥控器的键、其余放行；日志里每一条 PASS/SWALLOW 都记了 vk             |
| 3 | **往本机根证书存储装证书**   | **中**  | 修改信任根，杀软会报"安全设置被更改"                 | 只装一个、可删（`certmgr.msc` → 受信任的根 → 删 `WinUHidPublisher`） |
| 4 | 改 BthPort ETW 注册表 | 低      | 改的是蓝牙日志参数                           | 三个值可一键恢复                                              |
| 5 | VB-CABLE 虚拟声卡     | 低      | 正规签名、被广泛使用                          | 官方安装包                                                 |
| 6 | 回环 UDP            | 低      | 只绑 127.0.0.1                        | 无                                                     |

### 反作弊（重点：**打游戏前请关掉**）

| 反作弊                      | 风险    | 说明                                                         |
| ------------------------ | ----- | ---------------------------------------------------------- |
| **Vanguard（Valorant）**   | **高** | 它对**未签名/自签名内核驱动**最敏感，可能直接拒绝启动或要求卸载。**玩 Valorant 前务必退出本程序** |
| **EAC（Easy Anti-Cheat）** | 中     | 一般容忍虚拟输入设备，但自签名驱动仍可能被标记                                    |
| **BattlEye**             | 中     | 同上                                                         |
| **Denuvo 等**             | 中低    | 主要扫注入/调试行为，我们不做注入                                          |

**这是唯一需要买家配合的动作：进游戏前退出程序（托盘右键退出）。**  
程序不需要常驻，用的时候再开——这一点必须写在文案里，不要含糊。

### 可以理直气壮说的

1. **代码全部开源**（MIT，两个仓库：Windows 版 / macOS 版），上面每一条都能在仓库里搜到对应代码。
2. **零联网**：不出网、不上传、无遥测，断网也能完整运行。
3. **零注入**：不碰其他进程，不读剪贴板，不截屏。
4. **全部可逆**：三个注册表值、一个启动项、两个驱动、一个证书，都有对应的卸载/恢复路径。
5. 需要管理员权限的只有两件事：装驱动、改那三个 ETW 注册表值。其余全程不需要。

## 四、如果你想进一步降低误报（后续可做）

1. **给 WinUHid 驱动买个 EV 代码签名证书**（约几百元/年）—— 这是把"中高"降到"低"的  
   唯一根本办法，也是买家信任度最高的一项投入。
2. **钩子改成按需安装**：只有设备处于键盘模式时才装，正常 ETW 模式下不装  
   （现在是无条件装，因为启动时不知道设备在哪种模式）。可减少一半的误报面。
3. **把三个 ETW 注册表值做成"一键恢复"按钮**，并在文案里给出恢复步骤。
4. 在 README 里加一节「Security & Anti-Cheat」，把本文的第二部分翻成英文。
