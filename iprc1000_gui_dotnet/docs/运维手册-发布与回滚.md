## 1. 推送（本沙箱环境的坑）

1. **必须绕过沙箱代理**，否则 `schannel: CONNECT tunnel failed, response 502`：
   ```bash
   env -u http_proxy -u https_proxy -u HTTP_PROXY -u HTTPS_PROXY git push origin main
   ```
   （curl 走代理是通的，git 的 schannel 走 CONNECT 会被拒 —— curl 用 OpenSSL）
2. **没装 `gh`**，建 Release 走 API，且**要用 curl，不要用 Python urllib**
   （同一 token / URL，urllib 走代理会被 GitHub WAF 挡回 400「Whoa there!」）：
   ```bash
   TOKEN=$(printf "protocol=https\nhost=github.com\n\n" | git credential fill | sed -n 's/^password=//p')
   # 建 Release（tag 已存在时**不能带 target_commitish** → Validation Failed；报错只给 field，要看 errors 数组）
   curl -s -X POST -H "Authorization: token $TOKEN" -H "User-Agent: curl-release-tool" \
        -H "Accept: application/vnd.github+json" -H "Content-Type: application/json" \
        --data-binary @body.json \
        https://api.github.com/repos/lymsiq/IPRC1000-Adapter/releases
   # 传附件（upload_url 去掉 {?name,label} 后拼 ?name=xxx）
   curl -s -X POST -H "Authorization: token $TOKEN" -H "User-Agent: curl-release-tool" \
        -H "Content-Type: application/zip" --data-binary @"F:/vibe/xxx.zip" \
        "https://uploads.github.com/.../releases/{id}/assets?name=xxx.zip"
   ```
3. **Python 不认 git bash 的 `/tmp` 与 `/f/...` 映射** —— 脚本里一律写 `F:/vibe/...`。
4. **提交信息用 `-F 文件`**，别用 `-m`（bash 会对反引号做命令替换）。

## 2. 发布流程

### 2.1 每次发版必须传 4 个附件

| 附件 | 作用 |
|---|---|
| `IPRC1000_Adapter.zip` | **固定名·主包** —— 永久链接靠它，缺了就是 404 |
| `IPRC1000_Adapter_v{版本}.zip` | 带版本号存档 |
| `IPRC1000_Adapter_full.zip` | **固定名·免运行时版** |
| `IPRC1000_Adapter_full_v{版本}.zip` | 带版本号存档 |

- v1.0.7 / v1.1.0 只传了带版本号那个 → 永久链接实测 **404**（v1.1.1 才发现）。
  包内「升级说明.txt」向用户承诺的正是固定名链接。
- `tools/package.py` 收尾会打印完整清单与 4 个 sha256，照着传即可。
- ⚠ **61 MB 的免运行时版上传经常断**（v1.2.5 实测：前 3 个都 201，第 4 个连接被重置、
  响应体为空 → JSON 解析报错）。**补传即可**，上传统一加
  `--retry 3 --retry-delay 5 --max-time 300`，并**传完必须核对附件数 = 4**
  （少一个固定名附件，永久链接就是 404）。

### 2.2 永久链接（发布后务必自测）

```
https://github.com/lymsiq/IPRC1000-Adapter/releases/latest/download/IPRC1000_Adapter.zip
https://github.com/lymsiq/IPRC1000-Adapter/releases/latest/download/IPRC1000_Adapter_full.zip
```

⚠ **`releases/latest/download/` 有 CDN 缓存**：刚发完版去探会指向**上一个** release 而误判 404。
探测时加 `-H "Cache-Control: no-cache"`，或等十几秒再探。

### 2.3 顺序（踩过才定的）

1. 改 `<Version>`（唯一来源：`iprc1000_gui_dotnet/IPRC1000Adapter.csproj`）
2. 写 CHANGELOG
3. **先 commit**，再 `python tools/package.py`
   → 否则 exe 的 `ProductVersion` 戳的是**上一个**提交，指不到含修复的 commit
   （v1.1.2 发版时实测踩到，重打一次才对上）
4. 打 tag、推 main + tag
5. 建 Release、传 4 个附件
6. 自测两个永久链接 + 真实下载比对 sha256

## 3. 编码约定（`package.py` 已机器校验）

| 类型 | 要求 |
|---|---|
| 包内 `.cmd` | **GBK**（中文 Windows 控制台 cp936） |
| 包内 `.ps1` | **带 BOM 的 UTF-8** |
| 应用写的日志 | 首次创建写 **UTF-8 BOM**，否则记事本乱码 |

- 判据**不是**"能否解码" —— **GBK 很宽容，UTF-8 字节串按 GBK 也能解出来**（只是乱码）；
  判据是**按该编码读出后中文关键字仍在**。
- ⚠ 用 Write 工具产出的 `.ps1` 是**无 BOM 的 UTF-8** → PS 5.1 按 ANSI 读 → 中文直接语法报错。
  **自己写的辅助 `.ps1` 一律纯 ASCII**（要中文就得先补 BOM）。

## 4. 交付形态与版本号

| 项 | 约定 |
|---|---|
| 打包输出目录 | `F:\vibe\IPRC1000_Adapter`（主包）/ `IPRC1000_Adapter_full`（免运行时版），**都不带版本号** |
| 打包命令 | `python tools/package.py`（先重编译再打包，两个变体 + 全套校验）|
| 压缩包 | 每个变体两份：`_v{版本}.zip` 存档 + 固定名 `.zip`（永久链接靠它）|

**为什么包名必须固定**：Windows 解压向导**按压缩包文件名建目录**；版本号命名每升一级就换目录，
桌面快捷方式随之失效。用户要的形态是「一个不带版本号的文件夹，每次只更新里面的内容」。

**版本号规则**：exe 有变化 → 升版本号；只改文档/工具、exe 字节未变 → 不升，刷新同一版产物即可。
`ui/app.js` 预览模式里有一份示例版本号，顺手同步（只影响浏览器预览与截图）。

## 5. 回滚的正确姿势

1. **先存档再清场**：`git checkout -b wip/xxx` → `git add -A`（连未跟踪文件一起收）→ commit →
   `git checkout main` 会自动把新增目录从工作区移除 —— 留档 + 清场一步到位。
2. 目标状态已在 HEAD 上时，`git checkout main` 就够，**不需要 `reset --hard`**。
3. 验收：重跑 `package.py` + `dotnet build` 0 警告 + 下载 GitHub 包逐文件 sha256 比对。
   **`ui/*.js|html|css` 是外挂文件、不打进 exe** —— 验界面要比 `IPRC1000_Adapter/ui/` 目录，
   grep exe 永远搜不到。
