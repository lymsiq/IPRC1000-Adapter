# IPRC1000 Adapter · 鼠标模式：实现与坑（v1.2.0）

> 内部文档（**不随包发**）。用户要的是「遥控器当鼠标用」：
> 方向键**按住拖动**即移动（带自适应增速），确认=左键、info=右键。
> 本文只记**结论、实测数字、以及踩过的坑**；程序性细节看代码注释。

---

## 1. ★ 根本约束：移动永远从「光标此刻所在处」起算

**全程只用 `SendInput` 的相对位移（`MOUSEEVENTF_MOVE`），程序里不许有任何一处把光标搬到固定位置。**

这是用户实测后**当场指正**的（原话：「你要先计算鼠标的当前位置，再在鼠标当前位置进行移动，
而不是固定位置呀」）。第一版在 `SetEnabled(true)` 里做了一次"主动自校准"，
它的做法是绝对定位到"虚拟桌面中心"再弹回 —— 两个后果：

1. 进鼠标模式那一刻**光标猛地跳走**；
2. 多显示器下"虚拟桌面中心"**正好落在两块屏的接缝上**。

`package.py` 有**两条反向断言**盯着 `MouseEngine.cs` 里不许出现 `MoveAbsolute` / `CenterAndSettle`。
自检里给"向右/向下留空间"用的 `EnsureRoom()` 也改成纯相对位移。

## 2. 增益怎么量（两条路，都不搬光标）

为什么非要量：阶段 0 实测本机严格 1:1，但那是在「指针精确度**关** + 指针速度**默认档**」下；
门店机器这两项都可能不同，写死像素就会走太快或太慢。

### ① 被动标定 `CalibrateFromUse()`（默认路径）
我们本来就要知道光标实际走了多少 —— 顺手把"**上一帧**发出去的位移"与"光标实际位移"对账即得增益。

- **必须在帧首采样**：放在 `Move()` 之后紧接着读，`GetCursorPos` 拿到的是**没生效的旧位置**
  （输入是异步处理的）。所以是"帧首发位移 → 下一帧首读结果"。
- 取 **40 个样本的中位数**压野值（用户同时推自己的鼠标会污染样本）。
- 靠近屏幕边缘、且移动方向朝外时位移会被系统裁掉 → **该样本作废**。
- 全程**一次都不多动光标**。

### ② 主动自校准 `Calibrate()`（只在用户点「重新自校准」时跑）
**就地**做 **±d 成对移动、净位移为 0**；贴近屏幕边缘时某一侧会被裁，
就取**没被裁的那一侧**的幅度。会有 ±24 px 的轻微抖动，用户点按钮时属于预期之内。

若小/大增量比值不一致（系统加速开着），界面提示"速度会与你调的值有偏差"。

## 3. 自检 `--mouse-engine-test`（8 条断言）与**判据选择**

| 断言 | 判据 |
|---|---|
| ① 开启鼠标模式**不发出任何移动注入**（不会跳到固定点）| **注入计数** |
| ② 未开鼠标模式时方向键不被引擎消费 | — |
| ③ 按住 right 光标向右移动 | 量光标 |
| ④ 自适应增速生效（后半段更快）| 量光标 |
| ⑤ 松开后引擎**立即停止注入**（不漂移）| **注入计数** |
| ⑥ 确认键 → 系统左键按下/抬起 | `GetAsyncKeyState` |
| ⑦ 斜向不超速（已归一化）| 量光标 |
| ⑧ 收尾后系统左键已抬起 | `GetAsyncKeyState` |

### ★ 为什么"该不该动"看注入计数、"动了多少"才量光标

**量光标会被"用户同时推鼠标"污染。** 本机实测踩到：开启鼠标模式期间光标动了 **643 px**，
而注入计数是 **0** —— 那 643 px 根本不是引擎干的，差点被当成回归。

所以给 `MouseInjector` 加了 `MoveEvents` / `ButtonEvents` 计数（**我方账本，不受外部干扰**），
量位移的断言则**重试 3 次取位移最大的一次**，报告里也写明"跑的时候别碰鼠标"。

> 方法论：**测量受外部干扰时，换一个不受干扰的判据，而不是放宽阈值。**

## 4. 为什么鼠标用 SendInput 而不用虚拟 HID

WinUHid 存在的唯一原因是**输入法会过滤注入的键盘事件**（检测 `KLLKHF_INJECTED`）；
**鼠标没有这层过滤** —— 浏览器 / Office / 输入法窗口都正常接受 SendInput 鼠标。
反过来，虚拟 HID 鼠标要多建一台设备、多一份驱动依赖，而 WinUHid 本身还有
"设备槽位被占 → 创建失败 → 静默退化成 SendInput"的既知问题。
代价：需要 raw input 的游戏会忽略注入鼠标 —— 本场景不需要。

**实测**：`SendInput` 单次 **286 µs**，批量 247 µs/事件（只快 1.2 倍）
⇒ 瓶颈在**每个鼠标事件的内核处理**，不在调用次数
⇒ 所以**不批量**，改为"降低 tick 频率 + **按实际时间算位移**"（60 Hz，速度与 tick 抖动解耦）。

## 5. 手感与实时校准区

- 起步 60 px/秒 → 0.7 秒斜坡升到 900 px/秒，二次曲线（`Math.Pow(t, 2)`）"慢起快走"。
  想精确点按钮就轻按，想横跨屏幕就按住。
- **斜向归一化**（×0.707）—— 不归一化的话斜着走快 41%。我们的"整份报告"模型天然支持多键同按。
- 浮点累加器：速度可能是 1.3 px/帧，直接取整会"走走停停"。
- **实时校准区是一张"小地图"**：光点 = **光标此刻的真实位置**映射到方格纸，
  而**不是**从固定点累加位移 —— 后者会漂、和真实光标对不上。
  桥接方法叫 `mouseSample`（**不许改回 `mouseDelta`**：它会诱使下一个人把位置丢掉）。

## 6. 安全网（比鼠标功能本身更重要）

卡住的左键会让你**点不了任何东西**，所以：

1. **按住超时**：方向键 8 s、鼠标键 10 s，到点无条件放开；
2. **切模式 / 退出 / 紧急复位**一律 `ReleaseAll`（把所有鼠标键抬起）；
3. **鼠标键孤儿回收**：定期问系统 `GetAsyncKeyState(VK_LBUTTON/VK_RBUTTON)`，
   "系统说按着、我们没持有"且持续 ≥15 s → 补一次抬起。**以系统状态为准**，
   与键盘那边的孤儿键回收器同一思路（卡键根因就是"账不可靠"）。
   15 s 门槛是为了不误伤真人拖拽，且每次都写日志可查。

## 7. ★★ 模式就是配置组（v1.2.4 重构）

**以前**："键盘/鼠标模式"（存 `mouse.json`）和"配置组"（存 `keymap.json`）是**两套独立状态**
—— 于是会出现"切到了鼠标模式组，但模式还是键盘"这类谁都说不清的组合；
方块键的行为还要靠 `squareKeyAction` 这个二选一设置来定。

**现在只有一个状态来源**：

> **鼠标模式 = 活动配置组是不是「鼠标模式」组**（`Keymaps.MouseGroupActive`）。

- 配置组固定三个：**默认配置组 1（plain）/ 鼠标模式（`kind="mouse"`）/ WorkBuddy 快捷键（workbuddy）**。
  鼠标组插在第一个 plain 组之后，于是方块键「切配置组」的顺序是 默认 → 鼠标模式 → WorkBuddy → 默认。
- `Backend.SyncMouseWithGroup()` 是**唯一**同步点：切组（`CycleGroup` / `SwitchGroup` / `NewGroup` /
  `setMouseMode`）之后都调它，让 `MouseEngine.Enabled` 跟着组走。
- 「鼠标模式」组**不允许删除**（`Keymaps.Delete` 挡掉）—— 它是这个功能的唯一入口。
- 组里的默认映射 = `Defaults.Plain()` **原样，只把四个方向键清空**：
  方向键由引擎线程接管（按住加速移动），走不了普通映射；其余键（确认/info/语音…）
  沿用默认组，**并且可以随意改**。

### 方块键回归普通可绑定键

以前它是"硬编码的特殊键"，行为由 `squareKeyAction` 决定；现在它就是一个普通键，
出厂值 = 动作值 **「切换配置组」**（`KeyAct.SwitchGroup = -5`），在弹窗里能改成任意键/动作。
`Backend.NoteButton` 里那段方块键特例、以及 `MouseEngine` 的 `SquareKeyAction` 配置项**都已删除**
（`package.py` 有反向断言盯着不许复活；旧 `mouse.json` 里残留的字段会被静默忽略）。

### 引擎接管范围收窄

`MouseModeRouter` 现在**只接管四个方向键**（以前还接 确认/info → 左/右键）。
想恢复"按住方向 + 按住确认 = 拖拽"，就在鼠标组里把确认配成「鼠标左键」。

### 迁移（`Ver_ = 10`）

旧配置启动时：补出鼠标组（只在没有时）+ 把**空着的**方块键写成出厂动作。
★ **只在该键当前为空时才写** —— 用户若已手动绑过别的，一律不覆盖
（实测：`favorite=Ctrl+C` 之类的个性化设置全部原样保留）。

## 8. 踩过的坑

1. **量位移前先让光标停稳**：归位后不等停稳就读，拿到的是上一个位置
   （实测把向右的移动读成 **−1234 px**）。
2. **先校准量具再量目标**：探针一开始把 1:1 的映射读成 5× —— 根因是 CLI 分支跑在
   `ApplicationConfiguration.Initialize()` 之前、进程 DPI 不感知，`GetCursorPos`
   返回虚拟化坐标。**测量工具本身必须先验证。**
3. **绝对定位归一化的是整个虚拟桌面**（0..65535），不是主屏 —— 双屏下按主屏算会落在左半边。
4. **配置项大小写**：`PropertyNameCaseInsensitive` 不打开时，手改 `mouse.json` 写 camelCase
   会**静默失效**；非法值会**静默生效**。现在范围夹取 + 枚举校验抽成 `Sanitize()`，
   文件与界面**共用同一道闸**。
5. **界面约定**：说明文字用 `.note`（空则不显示）；`.warn` 是强调不是显隐开关；
   次要按钮折进 `<details class="adv">`；同一份数据不许在两个面板各显示一次
   （⇒ "配置组切换"没有在鼠标页重复放控件）。
6. **新增页面要同步改三处**：`ui_probe.js` 的 `PAGES`、导航按钮、`boot()` 预览分支里
   那串 render 调用（漏了最后一个 → 页面在预览/截图里是空的）。
