# 安全与反作弊说明（v1.2.67）

> 适用范围：IPRC1000 Adapter（Windows）。**单机工具**，设计前提是"本机、本人使用"。

---

## 一、攻击面与已实施缓解

| # | 攻击面 | 现状 | 风险 | 已实施缓解 |
|---|---|---|---|---|
| S1 | **UDP 31680/31681 无鉴权** | 只绑定 `127.0.0.1`，载荷格式严格校验 | 中 | 仅回环 + 严格语法（非法包直接丢弃）+ 长度/取值夹取 |
| S2 | 以**管理员**身份注入输入 | 必需（ETW + 驱动） | 中 | 只注入"遥控器映射出来的键"，不读用户输入内容 |
| S3 | 加载 `WinUHid.dll` / 安装虚拟 HID | 包内自带、不联网下载 | 低 | 第三方二进制**不进仓库**，只进发布包；`--revert` 可还原 |
| S4 | 读取注册表（设备识别） | 只读 | 低 | 不写注册表（除驱动绑定，需显式点按） |
| S5 | 音频经 VB-CABLE | 本机虚拟声卡 | 低 | 不保存音频、不联网 |
| S6 | 日志含设备 MAC / 按键 | `errors.log` 记 VOICE 事件，**不记内容** | 低 | 只留当天 + 20MB 截断；不记录语音内容 |
| S7 | exe 未签名 | — | 低 | 无法规避；用户可从源码自编译核对 |

### S1 为什么"已接受"

本机**同用户会话**的任意进程本来就能直接 `SendInput` 注入输入，再加一个 UDP 入口的**增量风险有限**。
唯一实质性威胁是"低权限进程借管理员身份的适配器向高权限窗口注入" ——
要堵住它需要**命名管道 + DACL**（UDP 加 token 没用：token 会出现在子进程命令行里，同用户可读）。
**结论**：记录为已接受风险；若将来要求更高，应改为"命名管道 + 只允许同完整性级别"，而不是给 UDP 加 token。

## 二、反作弊兼容性（重点）

### 2.1 我们的技术栈会被看到什么

| 技术 | 反作弊可见性 | 说明 |
|---|---|---|
| **低级键盘钩子 `SetWindowsHookEx(WH_KEYBOARD_LL)`** | 极易检测 | **★ v1.2.63 已彻底移除**（运行时零调用）|
| `SendInput` 注入 | 易检测（`LLKHF_INJECTED` 标志）| 仅在虚拟 HID 不可用时回退；**鼠标点击必用** |
| **虚拟 HID 键盘（WinUHid）** | 可枚举（多出一个 HID 键盘设备）| 主力注入通道 |
| ETW 会话（BthPort）| 可枚举（`logman query -ets`）| 只读，不改系统行为 |
| 管理员权限 + 未签名 exe | 白名单机制不友好 | 无法规避 |

### 2.2 风险评估矩阵

| 反作弊 | 内核级 | 对虚拟 HID / SendInput 的态度 | 建议 |
|---|---|---|---|
| **Vanguard**（Valorant）| 是 | 严格；虚拟输入设备**高度可疑** | **不要使用** |
| **Easy Anti-Cheat** | 是 | 视游戏；常见"未经授权的输入设备" | 不建议 |
| **BattlEye** | 是 | 同上 | 不建议 |
| **nProtect / XignCode3** | 是 | 常见于韩系网游，倾向拦截 | 不建议 |
| **TP / ACE**（腾讯系）| 是 | 有虚拟设备检测 | 不建议 |
| 单机游戏 / 无 AC 的联机 | — | 无影响 | 可用 |

### 2.3 已实施：**检测 + 如实提示**（v1.2.67）

- 每 32 秒检查一次已知反作弊进程（`vgc` / `vgtray` / `EasyAntiCheat` / `BEService` / `GameGuard` /
  `XignCode` / `ACE-Guard` / `TP` / `SGuard`）；
- 检测到 → **概览页顶部显示红色警告**，说明"虚拟 HID 可能被判违规、存在封号风险"；
- **不改变任何行为**（不自动停注入）—— 擅自停会让"在游戏里用遥控器打字"这类正当用途也失效。

### 2.4 如果一定要在游戏里用：唯一相对安全的路径

**把遥控器还原成普通键盘**（环境设置 → 切换设备驱动 → 还原为 HID Keyboard），
此时输入由**遥控器自己的 HID 键盘**发出，对反作弊而言就是**真实键盘**。

- 代价：`m` 幽灵键会漏进窗口（历史问题）；
- 收益：**不被判为虚拟输入设备**。

## 三、稳定性边界（已核对）

| 场景 | 处理 |
|---|---|
| 目标窗口 0×0 / 超 4000px | 直接跳过并报错 |
| 模板为空 / 损坏 / 大于窗口 | 提示重采 |
| `Active` 组索引非法 | 夹取 + 兜底组（v1.2.64）|
| `keymap.json` 损坏 | 回落出厂映射 + `errors.log` 留痕 |
| 系统把按住丢了 | `CheckHeldHealth` 300ms 内补回 |
| 音频输出"假正常" | `PlaybackState != Playing` 时重建（v1.2.26）|
| 日志写盘阻塞热路径 | **v1.2.67 改为异步入队** |

## 四、残余风险（明确列出，不掩饰）

| # | 风险 | 严重度 | 说明 |
|---|---|---|---|
| R1 | UDP 无鉴权 | 中 | 见 §1 分析；改为命名管道才能根治 |
| R2 | 反作弊封号 | **高**（对在线竞技游戏） | 技术栈决定，无法在"虚拟 HID"前提下规避；已用警告提示 |
| R3 | 管理员权限运行 | 中 | 必需；不做额外提权 |
| R4 | 未签名 exe | 低 | 可被 SmartScreen/UAC 拦截，属预期 |
| R5 | 虚拟 HID 与某些安全软件冲突 | 低 | 若被杀软拦截，会退化为 `SendInput` 并在日志写明 |
