# 换机部署清单

> 适用：把这个遥控器适配器装到**另一台 Windows 电脑**上。
> 结论先说：**不需要安装包也能一步到位** —— 解压后双击 `部署.cmd` 即可，它会自动完成 5 件事。
> 只有 3 个动作必须由人来做（UAC、蓝牙配对、确认驱动已切换）。

---

## 一、前提（缺一不可）

| 项 | 要求 | 怎么确认 |
|---|---|---|
| 系统 | **Windows 10 / 11 64 位** | `winver` |
| 蓝牙 | **支持 BthPort ETW 的内置/外置适配器** | 设备管理器 → 蓝牙，有正常设备即可 |
| 权限 | **管理员**（ETW 会话 + 驱动安装必需） | 双击 `部署.cmd` 会自动弹 UAC |
| 遥控器 | 已与这台电脑**完成蓝牙配对** | 设置 → 蓝牙 → 添加设备 |

### 不需要做的事（常见误解）

| 误解 | 事实 |
|---|---|
| "要关 Secure Boot / 开测试签名" | **不需要**。WinUHid 是 **UMDF 用户模式**驱动（`WinUHidDriver.dll`），自带 `.cat` 签名，Secure Boot 开启状态可正常加载（本机实测：Secure Boot 开、未开测试签名、5 个虚拟 HID 设备均 OK） |
| "要装 Visual C++ 运行库" | 不需要，包内组件不依赖 VC++ 运行库 |
| "要联网装驱动" | 不需要。声卡驱动包、虚拟 HID 都在 `assets/` 里 |
| "要手动装 .NET" | 免运行时版（`IPRC1000_Adapter_full.zip`）自带；主包由 `部署.cmd` 自动装 |

---

## 二、部署三步

### 1. 解压

解压到**固定目录**（例如 `D:\IPRC1000`）。
⚠ 不要放在桌面或"下载"里 —— 压缩包名带版本号会让桌面快捷方式失效，路径变动也会让快捷方式指向空。

### 2. 双击 `部署.cmd`

它会**自动提权**，并依次完成：

```
⓪ 确保 .NET 桌面运行时（已有则跳过）
① 安装 WinUHid 虚拟键盘驱动（注入"右 Alt 长按说话"必需）
② 把遥控器的 HID 驱动从"键盘"切换成"普通 HID 设备"（用 Windows 自带 input.inf，不装新驱动）
③ 安装 VB-CABLE 虚拟声卡（输入法转写用的音频回环）
④ 启动主程序（它会自动设为默认录音设备、拉起语音桥）
```

看到 `[done]` 即结束。若中途提示**需要重启**，重启后**再双击一次** `部署.cmd`（已完成的步骤会自动跳过）。

### 3. 人工确认三件事

| # | 动作 | 在哪看 |
|---|---|---|
| 1 | **蓝牙配对遥控器** | 设置 → 蓝牙 → 添加设备（部署脚本不管这一步） |
| 2 | 面板「环境设置」→ **一键完成全部**，看是否全绿 | 有红项就按提示点 |
| 3 | 按一下语音键，确认输入法弹出麦克风 | 没有反应 → 见下一节 |

---

## 三、常见失败与处理

| 现象 | 原因 | 处理 |
|---|---|---|
| `部署.cmd` 一闪而过 | 没找到 `tools\一键部署.ps1`（把 cmd 单独拷出来了） | 保持包结构完整 |
| UAC 点了"否" | 未提权 | 重新双击，点"是" |
| WinUHid 装完设备显示 **Stopped** / `problem≠0` | 旧节点是坏的，或旧版写坏 HardwareID | 双击 `assets\winuhid\Run-Install-Force.cmd`（**v1.2.82 起会先清空所有旧节点再重建**，见 §六）|
| 面板显示"设备仍是键盘" | 第 ② 步没生效 | 环境设置 → 切换设备驱动 → 重试；不行就拔插一次遥控器 |
| 语音键没反应、日志有 `INJ ... via=winuhid` 之外的回退 | 虚拟 HID 不可用，退化成 `SendInput`（会被输入法过滤） | 重装 WinUHid（同上） |
| 有麦克风图标但**没电平** | 音频输出通道"假正常" | 面板点「重建音频通道」；或重启程序 |
| 杀软拦截驱动安装 | 未签名的**安装脚本**被拦 | 允许后重跑；安装脚本本身未签属正常 |

---

## 四、卸载 / 回滚

| 要做什么 | 怎么做 |
|---|---|
| 恢复遥控器为普通键盘 | 环境设置 → 切换设备驱动 → 还原为 HID Keyboard |
| 移除虚拟键盘驱动 | `assets\winuhid` 下运行带卸载参数的安装脚本（见同目录《安装说明》） |
| 彻底清干净 | 删程序目录 + 设置里的开机自启项 + 卸载 VB-CABLE（控制面板） |

---

## 五、换机后要重做的事（配置不会跟人走）

`settings.json` / `keymap.json` 存在 **`%APPDATA%\IPRC1000 Adapter\`**，不随包分发。换机后需要：

1. 重新「采集」截图点击的图标（模板是**这台机器**的像素）；
2. 重新校准鼠标增益（面板 → 鼠标模式 → 校准）；
3. 按键映射若已自定义，把 `keymap.json` 拷过去（面板有「导出/导入」）。

> 想连配置一起带走：复制 `%APPDATA%\IPRC1000 Adapter\` 整个目录。
> ⚠ 里面包含**截图模板**（base64）与**命中位置**，换机/换分辨率后建议重采。

## 六、驱动装不上时：先抓诊断，别再猜

v1.2.82 起，安装脚本会把每一步写进日志，并提供**只读诊断**模式。远程排障时让对方跑这一条
（在管理员终端里，把路径换成实际目录）：

```
cd "<解压目录>\assets\winuhid"
.\install-winuhid.ps1 -Mode Status
```

输出形如（本机实测，全部正常）：

```
Phase: Diag | OS: Microsoft Windows NT 10.0.26300.0
Phase: Diag | Admin: True
Phase: Diag | Cert file thumbprint: FBC62729...
Phase: Diag | Cert in Root: True
Phase: Diag | Cert in TrustedPublisher: True
Phase: Diag | Device nodes: 7
Phase: Diag |   ROOT\WINUHID_VIRTUAL_HID_ENUMERATOR\0000  status=OK  problem=0
Phase: Diag | Interface \\.\WinUHid reachable: True
Phase: Diag | WudfRd: Running          ← UMDF 框架服务
Phase: Diag | WUDFHost processes: 2
Phase: Diag | SecureBoot: True
Phase: Diag | HVCI running: True
```

日志落在 `%LOCALAPPDATA%\com.remote-bridge-hub.app\winuhid\install.log`（超 512 KB 自动轮转到 `.old.log`）。

### 对照表

| 诊断 | 病因 | 处理 |
|---|---|---|
| `Cert in Root / TrustedPublisher: False` | 证书没导入（组策略或杀软拦截；静默模式下 .NET 的 `X509Store.Add` 可能弹"安全警告"而失败）| 管理员执行 `certutil -addstore -f Root WinUHidPublisher.cer`，TrustedPublisher 同理。**v1.2.82 起脚本会自动退回 certutil，不再弹窗** |
| `Device nodes` 里有 `problem≠0` | 坏节点残留 | 用 `-Force` 重装（见下）|
| `Device nodes` 数量 > 3 | 每次重装**叠加**新节点而非替换 | 同上；`-Force` 会清空全部 |
| `reachable: False` 但 `status=OK` | 接口被占用／句柄未释放 | 退出程序再开；仍不行重启 |
| `WudfRd: Stopped` | UMDF 框架没跑 | `sc start WudfRd` |

### 彻底重装（v1.2.82 的行为）

```
cd "<解压目录>\assets\winuhid"
.\install-winuhid.ps1 -Mode InstallElevated -Force
```

`-Force` 会：**删掉所有 WinUHid 节点**（不只坏的）→ 删旧驱动包 → 重导证书 → 重新注册**唯一**一个节点。

> 为什么要"全删"：本机实测已有 **7 个** `ROOT\WINUHID_VIRTUAL_HID_ENUMERATOR\000N`
> （每装一次多一个）。坏节点或旧节点混在里面时，设备可能绑到旧实例上，
> 于是"重装也修不好" —— 这正是本次修复的核心。

## 附录：为什么不做成"原生 exe"

经常被问：能不能编译成一个不依赖 .NET 的原生程序？

- **.NET 8 的 NativeAOT 不支持 WinForms**（官方限制），"同一套代码 + AOT"这条路不通；
- 实际等效做法是**自包含发布** —— `_full` 包与安装器都是这个，机器上有无 .NET 都能跑；
- 真要原生，只能**换掉外壳**（Rust / C++ 写窗口 + WebView2 宿主），预计 3~5k 行，
  注入／卡键／音频全部要重新回归；收益仅体积 61 MB → 约 5 MB、启动快约 0.5 秒。

**结论**：现阶段不重写，用自包含包解决"依赖 .NET"的实际问题。
