# IPRC1000 遥控器适配器 · SOP（部署与使用规范）

> 版本：2026-10-14 · 适用：Windows 10/11 x64

---

## 一、这是什么

把**蓝牙语音遥控器**变成电脑的**语音输入 + 快捷键盘**：

- 按住遥控器的【语音键】说话 → 自动向系统注入**右 Alt（按住不放）** → 豆包输入法的「长按模式」开始收音
- 遥控器的方向/确认/返回/音量等键 → 注入对应的**系统快捷键**（见《遥控器按键说明》）
- 最底部的【方块键】→ **循环切换配置组**（默认组 ↔ WorkBuddy 快捷键组）

## 二、部署（首次）

### 需要什么

| 依赖 | 必需 | 怎么来 | 备注 |
|---|---|---|---|
| **管理员权限** | ✓ | 部署脚本会自己提权 | ETW 抓包 + 驱动安装都要 |
| **.NET 8 Desktop Runtime** | ✓ | 微软官网 / `winget install Microsoft.DotNet.DesktopRuntime.8` | 主程序是框架依赖发布 |
| **WebView2 Runtime** | ✓ | Win10/11 一般自带；没有就装 Evergreen | 界面渲染 |
| **WinUHid 驱动** | ✓ | **包内自带**（`assets\winuhid`） | 注入右 Alt 说话必需 |
| **VB-CABLE 虚拟声卡** | ✓ | **包内自带**（`assets\VBCABLE_Driver_Pack45.zip`） | 音频回环，豆包转写用 |
| **遥控器蓝牙配对** | ✓ | 系统蓝牙设置里配对 | 设备名 IPRC1000 |
| **设备驱动切换** | ✓ | **脚本自动做，不需要新驱动** | 见下方"④"的说明 |

> **重点：第 7 项不需要下载任何驱动。** 我们只是把遥控器的设备驱动从 Windows 自带的
> `kbdhid`（键盘）换成同样自带的 `input.inf → HID-compliant device`（普通 HID）。
> **这是为了让系统不再把它当键盘** —— 当键盘时系统会合成 `m`、幽灵报告会变成 `i`、
> 拔电池还会把键锁在"按下"一直刷屏。换成普通 HID 后这些问题从根上消失。

### 一键部署步骤

1. 解压 `IPRC1000_Adapter_v1.0.zip` 到任意目录（**路径别带中文空格也行**）
2. `右键 → 使用 PowerShell 运行` **`tools\一键部署.ps1`**（会自己提权）
3. 脚本依次完成：① WinUHid 驱动 ② 设备驱动绑定 ③ VB-CABLE ④ 启动主程序
4. 主程序启动后**自动完成**：默认录音设备设为 CABLE Output → 拉起语音桥 → 自动切非键盘驱动 → 应用按键映射
5. 打开主程序「环境设置 → 环境自检」，确认 **5 项全绿**：

```
虚拟声卡 ✔   默认录音设备 = CABLE Output ✔   WinUHid 驱动 ✔
按键受保护 ✔（遥控器已不是键盘·零 m）        语音桥 ✔
```

### 如果自检有红项

| 红项 | 处理 |
|---|---|
| 虚拟声卡 | 重跑部署脚本第 ③ 步（会弹 VB-CABLE 安装窗，需点 Install Driver）|
| 默认录音设备 | 主程序里点「一键完成全部」→ 它会用系统 API 设置默认录音设备 |
| WinUHid 驱动 | 重跑第 ① 步；仍不行看 `assets\winuhid\安装说明.txt` |
| 按键受保护 | 点面板「切换设备驱动」（等价于脚本第 ② 步）|
| 语音桥 | 看面板的「音频帧」是否随说话增长；不涨就重启主程序 |

## 三、日常使用

1. **语音输入**：按住遥控器【语音键】不放 → 对着遥控器说话 → 松开。豆包会自动把文字落到光标处。
2. **切换配置组**：按遥控器**最底部的方块键** → 右上角提示当前组名，循环切换。
3. **快捷操作**：按《遥控器按键说明》里的键位表使用。
4. **托盘**：点窗口右上角 `X` = 最小化到托盘（语音桥不中断）；双击托盘图标恢复；右键「退出」才是真退出。
5. **开机自启**：环境设置 → 环境自检 → 「开机自启」「启动时进托盘」可开关。

## 四、改按键

「按键映射」页：

- **左**：遥控器实体图 —— 点某个键或点右侧某一行，遥控器上会**青色高亮**对应的键
- **右**：23 个按键，每行显示**该键的缩略图**（从遥控器照片裁出）+ 当前映射
- **改法**：点某一行 → 弹出**屏幕键盘** → 先点修饰键（`Ctrl` / `Alt` / `Shift` / `Win`，可多选）再点主键 → 「保存映射」
  - 只点修饰键也能保存（单独注入修饰键）
  - 点「不执行」= 该键不注入任何按键
  - 媒体键（播放/暂停、上下曲、音量、静音）在键盘下方一排
  - **关闭弹窗**：右上角 `×` / 点弹窗外空白处 / 按 `Esc`，三种都行
- **`info`（信息键）默认不映射**：试过 `Alt+Enter` / `Ctrl+Enter` / `/` 都无感，所以留空。
  想用就照上面的改法自己设。
- **配置组**：顶部 Tab
  - `+` = **复制当前映射并新建一组**（自动编号）
  - 单击 Tab 切换 · **双击 Tab 重命名** · `−` 删除（至少保留一组）
  - 搜索框：按 **按键名 / 显示标注 / HID 值 / 映射动作** 过滤
  - 「导出」只导出**当前组**；「导入」只替换**当前组**，不影响其它组
- **恢复默认**：把**当前配置组**恢复为出厂映射（不是全部）✓

> 配置存在 `%APPDATA%\IPRC1000 Adapter\keymap.json`（多组 + 当前组）。
> 首次运行给两组：**默认配置组 1**（Windows 日常）和 **WorkBuddy 快捷键**。
> 遥控器最底部的**方块键固定用于切换配置组**，不可改为其它动作。

## 五、排障

| 现象 | 原因 | 处理 |
|---|---|---|
| 按键有 ~50 ms 延迟 | ETW 投递（正常，已用"填缓冲"压到 ~13 ms） | 看「按键来源」面板的 ETW 投递延迟；活跃时约 13 ms、空闲约 200 ms |
| **改了映射按下去没反应**| ①程序没重启（映射在启动时读一次）② 见下方"映射自检" | 右键托盘退出后重开；再不行跑一次映射自检 |
| 遥控器按键打进窗口（出现 m / i）| 设备驱动被系统还原成键盘 | 面板点「切换设备驱动」，或重跑部署脚本第 ② 步 |
| 键盘某个键失效 / 一直重复 | 注入的键被锁在"按下" | 面板点「紧急复位：释放所有按键」；或跑 `tools\stuck_key_guard.py --once` |
| 说话没反应 | 语音桥没起 / 默认录音设备不对 | 看「语音桥」面板的音频帧；重跑「一键完成全部」|
| 中文输入法打不出中文 | 一般是输入法被切到英文（**不是本程序的锅**）| 按 `Shift` 切中/英，或 `Ctrl+空格` / `Win+空格` 换输入法 |
| 遥控器连不上 | 蓝牙配对丢了 | 系统蓝牙设置里重新配对 |

### 映射自检（改了映射没反应时先跑这个）

```powershell
& "IPRC1000 Adapter.exe" --map-dump "$env:TEMP\map.txt"; notepad "$env:TEMP\map.txt"
```

它会打印**每个键的三列**：`实际注入` / `界面显示` / `出厂默认`。

```
menu          0x11   菜单键            菜单键            菜单键            OK        OK
back          0x09   Backspace         Backspace         Backspace         OK        OK
```

- 前两列**一致** → 程序读到了你的配置。那么"没反应"通常是**目标程序里这个组合键本来就没有功能**
  （例：`Ctrl+Enter`、`/` 在多数程序里无动作；且需要先点进一个输入框）。
  换个有全局效果的键验证：`pwr`（Win+L 锁屏）、`menu`（右键菜单）—— 这两个按下去一定有反应。
- 第三列标 `≠` → 该键与出厂默认不同（你自己改过，属正常；除非你要把当前值冻结成默认）。
- 出现 `★不一致★` → 报告这个表格，是程序 bug（说明注入与界面读了不同的数据源）。

> **必须重启程序**：映射在程序启动时读一次、常驻内存；改完配置（或换了新 exe）后
> 要**右键托盘退出**再重新打开，否则跑的还是旧映射。

### 全量自检

```powershell
& "IPRC1000 Adapter.exe" --selftest "$env:TEMP\selftest.json"; notepad "$env:TEMP\selftest.json"
```

报告含运行状态（按键来源 / 设备是否还是键盘 / 注入开关 / 虚拟键盘驱动 / 环境就绪项）与界面探针。

> ⚠ 自检要开 WebView2 界面，**必须在有交互桌面的会话里跑**。无桌面环境下 WebView2 起不来，
> 自检会如实把 `source` / `jsProbe` 记为错误（这是设计好的降级，不是崩溃），
> 并在 `<报告>.trace.log` 留下执行轨迹。

**日志**：`%APPDATA%\IPRC1000 Adapter\key-events.log`（按键全过程）· `stuck-guard.log`（卡键救援）

日志里每行形如：

```
14:22:56.387  KEY  usage=0x0B  info  DOWN  投递延迟=8ms     ← ETW 收到遥控器按键
14:22:56.388  APPLY  info  DOWN  来源=etw  映射=Ctrl+enter  组=默认配置组 1   ← 按配置注入
14:22:56.410  INJECT DOWN 0x11+0x0D via=winuhid            ← 真正打进系统
```

三段齐全才算走通。缺 `APPLY` = 该键没配映射；缺 `INJECT` = 注入被关（面板「开启快捷键注入」）。

## 六、附带工具（`tools\`）

| 工具 | 用途 |
|---|---|
| `一键部署.ps1` | 首次部署（驱动 + 设备绑定 + 声卡 + 启动）|
| `SetHidDriver.exe` | 单独切设备驱动：无参数=非键盘 / `--revert`=键盘 / `--models`=列出型号 |
| `stuck_key_guard.py` | 独立卡键守卫（`--install` 加开机自启、`--once` 单次检查）|
| `Run-Guard.cmd` | 守卫的提权启动器 |
| `check_stuck_key.py` | 卡键根因检查（读系统键盘状态 + 设备是否在线）|
| `package.py` | 开发用：一键打包 + 校验包内容（打包前自动重新编译，共 21 项校验）|
| `IPRC1000 Adapter.exe --map-dump <文件> [组号]` | 打印「实际注入 / 界面显示 / 出厂默认」三列，核对是否一致（排障首选）|
| `IPRC1000 Adapter.exe --inject-test <文件>` | 注入自检：虚拟 HID 与 SendInput 两条通路 |
| `IPRC1000 Adapter.exe --inject-verify <十六进制VK>` | 单键注入验证：按住时读 `GetAsyncKeyState` 判断系统是否收到 |
| `IPRC1000 Adapter.exe --selftest <文件>` | 全量自检（**需交互桌面**；无桌面环境下 WebView2 起不来）|

## 七、卸载 / 还原

1. 主程序面板取消「开机自启」，右键托盘「退出」
2. 想把遥控器还原成键盘：`tools\SetHidDriver.exe --revert`
3. 卸载 WinUHid：控制面板 → 程序和功能
4. 卸载 VB-CABLE：同上（或用它的卸载程序）
5. 删除程序目录即完成（绿色版，不写注册表安装项）；配置在 `%APPDATA%\IPRC1000 Adapter\` 可一并删除
