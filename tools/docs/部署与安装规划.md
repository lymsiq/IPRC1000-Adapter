# 多机器 / 多环境 部署与安装规划

> 2026-10-29 ｜ 对照项目：[GetSayAll/remote-mic-app-windows](https://github.com/GetSayAll/remote-mic-app-windows)（同形态、小米遥控器）

---

## 一、先讲清：为什么"零依赖"在我们这儿做不到，而他们看起来做到了

| 项 | SayAll（小米 RC001/RC003）| 我们（IPRC1000）|
|---|---|---|
| 遥控器音频怎么进电脑 | **标准蓝牙 HFP 耳机**（系统直接出现麦克风）| **ACL 上的私有协议**（不走 SCO，必须 ETW 抓帧 + 软件还原成 PCM）|
| 虚拟声卡 | **需要** VB-CABLE（同样要重启）| **需要** VB-CABLE |
| 虚拟 HID 驱动 | **不需要**（遥控器保持键盘，靠**钩子**捕获 + UAC 授权）| **需要** WinUHid（把遥控器从键盘切成普通 HID，消掉 31 Hz 幽灵 `m`）|
| 证书 | 不涉及 | 自签名 `.cat`，需导入 Root + TrustedPublisher |
| 日常权限 | **普通用户** | **必须管理员**（ETW `StartTrace` 要求）|

**结论**：他们的"简单"来自**设备形态标准**，不是工程更强。我们的三个硬依赖（ETW 需管理员、音频需还原、幽灵键需换驱动）都由**遥控器固件行为**决定，无法靠打包技巧消除。

**但可以做到"零运行库 + 零手工"** —— 这才是我们该承诺的目标。

## 二、依赖全景（谁装、能否一键、失败长什么样）

| 依赖 | 现在由谁装 | 一键? | 失败的表现 | 失败时我们给什么提示 |
|---|---|---|---|---|
| .NET 8 | 安装器自带（自包含 45.6 MB）| ✅ 无需 | — | — |
| WebView2 运行时 | 安装器在线装 | ✅ 自动 | 白屏 / 启动即退 | `webview.log` 不存在 → "WebView2 缺失，请点修复" |
| **VB-CABLE** | 安装器调官方 exe（**需人点 Install Driver + 重启**）| ⚠️ 半自动 | 有麦克风图标但**没电平** | 面板「重建音频通道」；诊断显示端点缺失 |
| **WinUHid 驱动** | 安装器调 `install-winuhid.ps1` | ✅ 自动（v1.2.82 起自愈）| 按键无反应、`via=sendinput` 回退 | 面板显示"虚拟键盘未就绪" + 修复入口 |
| **自签名证书** | 同上（脚本内导入）| ✅ 自动（certutil 兜底）| 驱动装完仍 Code 52 | 诊断里 `Cert in Root/TrustedPublisher: False` |
| **管理员权限** | 安装器提权 + 应用以管理员运行 | ✅ 自动 | ETW 起不来 → 无音频无按键 | 面板红色"缺少管理员权限" |
| 蓝牙适配器 | 用户 | ❌ | 遥控器连不上 | 引导去系统蓝牙配对（名称 IPRC1000）|
| 输入法（豆包/微信）| 用户 | ❌（不代装）| 按键注入了但没弹语音条 | 首页三档选择 + 检测提示 |

### 唯一"必须人工"的两步

1. **VB-CABLE 的 Install Driver + 重启**（VB-Audio 官方安装器不接受静默参数）
2. **蓝牙配对**（Windows 只允许交互式配对）

这两步无法自动化，但**可以做到"只做一次、有明确指引、失败能定位"**。

## 三、安装简化的下一步（按性价比）

### P0 — 已完成（本轮之前）

- 安装器一键：.NET / WebView2 / WinUHid / VB-CABLE / 快捷方式 / 卸载项
- **修复安装**：`-Force` 清空旧节点 → 重导证书 → 重建唯一节点（解决"重装也修不好"）
- **复制诊断**：`-Mode Status` → 桌面 txt + 剪贴板
- 证书：按指纹判重 → `X509Store.Add` 失败自动退回 `certutil -addstore -f` → 双存储复查

### P1 — 现状订正 + 剩余缺口

**① 环境体检：已存在，不需要重做**

应用「环境设置」页顶部已有 **「环境自检 · 一键就绪」** 面板 + **「一键完成全部」** 按钮，
`Backend.RunSetup()` 依次处理：虚拟声卡 → 虚拟键盘驱动 → 设备驱动 → 默认麦克风。
所以这里不缺"体检"，缺的是**用户看不懂时的一句话结论**（见 ②）。

~~安装器加「环境体检」一页~~ ← 原计划的这一项可以取消，不要重复造。

```
✔ .NET 运行时        自带
✔ WebView2           已就绪
✔ 虚拟键盘驱动        1 个节点 / 可访问
✔ 证书                Root + TrustedPublisher 均命中
✔ 虚拟声卡            CABLE Input/Output 均在
✘ 麦克风权限          请在 设置 → 隐私 → 麦克风 允许桌面应用
→ [一键修复全部]
```

价值：把"六项依赖各自失败的样子"收敛成**一屏红绿**，用户不用逐个点。

**② 错误码 → 中文建议（诊断里已部分实现）**

`-Mode Status` 末尾现在会输出一段 **`Phase: Advice`**：

```
Phase: Advice | 证书未在 TrustedPublisher → 在安装器点「修复安装」（会用 certutil 重新导入）
Phase: Advice | 设备节点 5 个，多于正常值（1~2）→ 点「修复安装」清理残留
Phase: Advice | 未发现需要处理的问题。      ← 健康机器
```

还没做的是**安装器失败页**也给出同样的一段（目前只在诊断里）。对照表如下：

| 退出码/现象 | 原因 | 建议 |
|---|---|---|
| 3010 | Windows 要求重启 | 重启后自动续跑 |
| `Code 52` | 驱动签名不受信 | 证书未导入 → 点修复 |
| `Code 10` | 设备无法启动 | 旧节点冲突 → 点修复（-Force）|
| `0x80070005` | 权限不足 | 用管理员重试 |
| `Pipe is broken` | 业务进程被结束 | 重新启动应用 |
| `short_pdu` 增长 | 音频帧长度不认识（换固件）| 发诊断，需适配帧格式 |

**统一话术三段式**：`发生了什么` → `为什么` → `你现在该做什么`。

### P2 — 可选（有明确代价）

**③ 零驱动模式 — ✅ 已实现（v1.2.93）**

开关位置：环境设置 → 与日志开关同排的 **「无驱动模式（降级）」**。

| 能力 | 标准模式（有驱动）| 无驱动模式（降级）|
|---|---|---|
| 按键映射 → 普通程序 | ✅ | ✅（走 SendInput）|
| **按住语音键触发输入法** | ✅ | ⚠️ **可能不生效**（IME 会过滤 SendInput）|
| 遥控器音频 → CABLE | ✅ | ✅ 不受影响 |
| 需要装驱动/证书 | 需要 | **不需要** |
| 幽灵 `m` | 由驱动消除 | 由钩子**只在按住语音键期间**吞掉 |
| 反作弊 | 虚拟 HID 可识别 | **钩子可识别**（同样是风险）|

实现要点：
- `GhostGuard`：低级键盘钩子，只在 `voice` 按下时武装，松开后 400 ms 宽限解除；
  **安全阀**：万一"松开"丢了，15 秒自动解除（避免 `m` 永远打不出来）。
- 语音键的 `Arm/Disarm` 挂在 `KeyFilter.ApplyButton`（两种按键来源的共用漏斗）。
- 自检：`IPRC1000 Adapter.exe --ghost-test` → 注入 3 个 `m`，应输出「已吞掉 3 / 3 个 m」。

实测（本机）：开 → 设备还原为 HID Keyboard；按住期间注入 5 个 `m` **全部被吞**；
关 → 设备切回 HID-compliant；随后注键 1 DOWN/1 UP 正常。

修掉的两个真问题：
1. `SetWindowsHookEx` 在新线程里装，`Start()` 必须**等它装完**再返回（否则误报安装失败）。
2. `SetDeviceDriver` 切换后**立刻复查**会误报失败（设备要重新枚举），且 `RemoteHwidsCache`
   有 **5 秒缓存** ⇒ 必须用 `force: true` 轮询。


- 做法：遥控器**保持键盘**，用低级键盘钩子**吞掉幽灵 `m`**。
- 收益：**不装驱动、不导证书、不需要换设备驱动** —— 受限机器（无管理员装驱动/杀软拦）也能用。
- 代价：**重新引入钩子** → 反作弊可检测；且钩子需要随程序常驻。
- 结论：做成**用户可选**，并在选择页明确写"仅建议在无联机游戏的机器上使用"。

### P3 — 大工程（仅在必要时）

**④ 把 ETW 桥做成 Windows 服务**，UI 降权运行。

- 收益：日常不需要管理员（对齐 SayAll 的"普通用户"体验）。
- 代价：服务安装/签名/升级/权限模型全套要重做，且服务与 UI 的 IPC 要重新设计（我们已有管道经验，可复用）。

## 四、多机器 / 多环境的健壮性清单

| 环境差异 | 我们的现状 | 待补 |
|---|---|---|
| Windows 10 1809~1909 | `pnputil` 缺 `/enum-devices`、`/remove-device` | 已加版本门槛 + `Get-PnpDevice`/`Remove-PnpDevice` 兜底 |
| Windows 10 2004+ / 11 | 主路径 | 实测仅 Win11 26300 一台 |
| **Win11 24H2** | 未验证（蓝牙栈有改动）| 需实测矩阵 |
| 4K / 超宽屏 | 窗口尺寸上限已放宽 + 自适应降采样 | — |
| 多显示器 / 缩放 125%~200% | 截图点击有多尺度 | 待多 DPI 实测 |
| 无网络（内网） | 安装器**本地优先**（VB-CABLE 用随包），WebView2 仍需联网 | 可提供离线 WebView2 包（+120 MB）|
| 杀软/EDR | 未签名的脚本会被拦 | 诊断能看出证书/节点异常；建议加"被拦截时的提示" |
| 换遥控器（多台）| 按**蓝牙名称 IPRC1000** 识别，不认 MAC/VID | 已支持多台（本机曾同时配对 3 个）|
| 换型号/新固件 | 音频帧格式写死（653/`A1 F7 01`/`40 01`）| **P0：桥记录"未知帧长 + 前 8 字节"**，便于 5 分钟适配 |

## 六、一句话目标

> **对外承诺**：装一次、重启一次，之后不再需要命令行、不再需要手动装任何东西。
> **对内承诺**：任何一步失败，用户能一键把"为什么"发给我们，而不是只能说"不好使"。

达不到的是"完全不装驱动/不要管理员"—— 那是**遥控器固件与 ETW 的约束**，不是我们能靠打包解决的。
