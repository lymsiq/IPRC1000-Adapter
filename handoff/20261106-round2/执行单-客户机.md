# 执行单 · 客户机「遥控器按键无反应」修复（Round 2）

> 目标机：客户机（`PC-20260728LQXO`，Realtek 8821CE）
> 依据：`handoff\20261106-round1\06-verdict.md`（S2 根因确认）+ `docs\开发-测试同步协议.md` R1–R3
> 本单只做一件事：**强制 Windows 重跑一次服务发现（SDP），把 HID 绑定建起来**。
> 版本：v0.4.41（含判据修复）

---

## 0. 一句话结论（可直接转述给客户）

> 遥控器和电脑之间**连得上、密钥也正常**，但 Windows 从未登记「这台设备是键盘」，
> 所以按键报文被主机拒收（`REFUSED_PSM`）。**遥控器没坏，软件也没装错**，
> 需要把配对删掉重配一次，让 Windows 重新识别设备类型。多数情况下 5 分钟内可恢复。

判据只有两条（`同步协议.md` R2）：

```
① Enum\BTHENUM\{00001124-0000-1000-8000-00805F9B34FB}_*  存在，且 Service = HidBth
② 配对记录下「缓存 SDP 服务记录」条数 > 0
```

两条同时满足 = 已修复。其余现象（程序绿/红、日志有无 KEY）都只是结果。

---

## 1. 先取证，再做任何操作（约 1 分钟）

在客户机执行（PowerShell，**普通权限即可**，脚本只读）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File Z:\vibe\iprc1000_native\tools\diag-bt.ps1
```

没有 `Z:` 映射 → 把 `tools\diag-bt.ps1` 拷到客户机桌面再跑。

**记录当前值**，尤其：

```
[C2] BTHENUM  是否有 {00001124-...} 节点 / Service 是什么
[C3] 缓存 SDP 服务记录: N 条
```

预期（修复前）：`无 {00001124}` + `0 条`。若与此不符，先停，把输出回传（判据变了，方案要重定）。

---

## 2. 重新配对（关键步骤，顺序不能错）

1. **删设备**：设置 → 蓝牙和其他设备 → 找到 `IPRC1000` → 删除设备。
2. **遥控器回可配对态**：同时按 **「上一频道 (last)」+「下方向键」**（若遥控器仍在旧链路里，先做这一步）。
3. **进配对模式**：长按右上角 **PWR**，直到方形指示灯 **蓝灯闪烁**。
4. **配对**：Windows → 添加设备 → 蓝牙 → 选 `IPRC1000` → 完成。
5. 配对完成后**按一下遥控器任意键**（唤醒 HID 通道）。

> ⚠ 不要在这台机器上点任何「改造成 HID 兼容设备 / 修复设备类型」类的按钮或脚本。
> 那会把 `kbdhid` 摘掉，按键从"能连不能用"变成"彻底死"，只能靠重装驱动恢复。

---

## 3. 立即判定（配对后 1 分钟内跑）

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File Z:\vibe\iprc1000_native\tools\diag-bt.ps1
```

| C2 / C3 结果 | 含义 | 下一步 |
|---|---|---|
| `{00001124}` 存在 + `Service = HidBth` + 记录数 > 0 | **修复成功** | 进第 4 步 |
| 有 `{00001124}` 但 `Service` 为空 | 节点建了、绑定没完成 | 重启电脑后再跑一次；仍为空 → 第 6 节硬件分支 |
| 仍无 `{00001124}` / 记录数 = 0 | SDP 在这块适配器上没跑起来 | 最多再重配 **1 次**；仍失败 → 第 6 节硬件分支，**不要再改软件** |

## 4. 装 v0.4.41（仅在第 3 步判为成功或"节点已建"之后）

```text
\\开发机共享\...\IPRC1000_Native_Setup_v0.4.41.exe    （或 Z:\vibe\IPRC1000_Native_Setup_v0.4.41.exe）
```

右键 → **以管理员身份运行**（安装器需要写 HKLM 与驱动；主程序本身不需要管理员）。

装完启动，**只看两处**：

1. 环境页「遥控器按键通道」= **绿**（`Service=HidBth`）。红 = 绑定仍未完成，回第 3 步判定。
2. 日志 `%APPDATA%\IPRC1000 Adapter\native.log` 出现：

```
[启动] 蓝牙 HID 服务已绑定（Service=HidBth）
[HID] Raw Input 设备: ...VID&00020a5c_PID&8502...   ← 设备名被认领
[KEY] usage=0x..                                     ← 按键到达
```

按一次遥控器按键，`native.log` 有 `[KEY]` 行 = 按键通道通了。
（无 `[KEY]` 但有 `[HID] 未认领` → 记录该行回传，属设备名过滤问题，不必再折腾配对。）

## 6. 失败分支（重要：不要无限重配）

前提：**已按第 2 节完整重配 2 次，C3 仍为 0 条**。

按成本从低到高，**一次只做一项，做完立刻跑 diag 判定**：

1. **更新蓝牙驱动**：Realtek 8821CE 组合卡（USB `VID_0BDA&PID_C821`）—— 到主板/整机厂商页面取最新蓝牙驱动（不要用 Windows Update 的通用版），装完**重启**。
2. **禁用/启用适配器**：设备管理器 → 蓝牙 → 右键禁用 → 启用（强制重新枚举）。
3. **换蓝牙硬件**（最有效，约 30–60 元）：
   - USB dongle：**RTL8761B** 或 **CSR8510 A10** 芯片（认准 **BR/EDR + HID Host**，纯 BLE-only 的 dongle 不行）；
   - 或换内置网卡 **Intel AX200 / AX210**。
   - 换完后从第 2 节重新配对，再跑第 3 步判定。

判定为硬件问题的依据：`L2CAP ConnReq PSM=0x0011` 照常发出，但主机侧始终没有监听者、SDP 记录恒 0 —— 说明这块组合卡的蓝牙固件在 HID Host 角色上没跑 SDP，与遥控器无关。

## 7. 明确不要做的事

| 禁止 | 原因 |
|---|---|
| 点「改造成 HID 兼容设备 / 一键修复设备类型」 | 摘掉 `kbdhid`，按键彻底死 |
| 跑 `--restore-keyboard` | 本故障无 `Enum\HID` 节点可恢复，无效 |
| 反复重配 5 次以上 | 不解决 SDP 层问题，只会浪费时间 |
| 依赖程序界面绿/红下结论 | 判据只认第 0 节两条注册表事实 |
| 在客户机上跑私有解析脚本出结论 | 违反 R3；一律用 `tools\parse_hci.py` |
