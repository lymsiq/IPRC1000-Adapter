# 交接：开发机（正常）vs 客户机（异常）—— 双机对拍检测

> 2026-11-06 · 目标：用**同一份脚本**把两台机器的状态各拍一张，逐行 diff，差异即病灶。
> 脚本：`tools/snapshot.ps1`（只读，不改任何设置）

---

## 0. 怎么用（3 步，5 分钟）

```powershell
# 两台机器各跑一次（普通权限即可，只读）
powershell -NoProfile -ExecutionPolicy Bypass -File <路径>\tools\snapshot.ps1
```

产出 `snapshot-<主机名>.txt`，然后对比：

```cmd
fc /n snapshot-开发机.txt snapshot-客户机.txt
```

或

```powershell
Compare-Object (Get-Content 开发机.txt) (Get-Content 客户机.txt)
```

## 1. 只有 4 个判据，其余都是结果

| # | 键 | 正常值 | 含义 |
|---|---|---|---|
| 1 | `bthenum_hid_bound` | `yes` | `Enum\BTHENUM\{00001124…}` 的 `Service=HidBth` ⇒ 主机 L2CAP 有 PSM 0x0011 监听者 |
| 2 | `btpair[n].sdpRecords` | `> 0` 且 `hasHIDservice=yes` | SDP 真跑过，服务缓存里有 HID 记录 |
| 3 | `enumhid_count` | `>= 1` | 遥控器的 HID devnode 存在 |
| 4 | `enumhid_service` | `kbdhid` | 绑键盘驱动 ⇒ Raw Input 能读到按键（代价：系统打字符） |

**四条全绿 = 按键一定能收到**。任何一条不满足，后面所有现象（界面红、无 `[KEY]`、语音没声）都是结果，不用再查。

## 4. 差异 → 修法

| 差异 | 修法 | 备注 |
|---|---|---|
| `enumhid_count=0` | 重启蓝牙适配器 + 按遥控器唤醒 | **不是重配对**。节点被删了，链路还挂着，必须断链重连才会重新枚举 |
| `enumhid_service` 空 / HIDClass | 点 ⑤ 恢复键盘模式 | 回到 `kbdhid` |
| `cable_present=no` | 装 VB-CABLE（`assets\VBCABLE_Driver_Pack45.zip`） | 装完重启 |
| `winuhid` 失败 | 装驱动 + **重启电脑** | 槽位被上次异常退出的进程占着 |
| `sdpRecords=0` | 删除设备 → 重新配对 | 详见 round2 执行单 |

**重启蓝牙适配器**（客户机是 USB 键鼠，安全）：

```powershell
# 管理员
$bt = Get-PnpDevice -Class Bluetooth | Where-Object { $_.InstanceId -match '^USB\\' }
$bt | Disable-PnpDevice -Confirm:$false
Start-Sleep -Seconds 4
$bt | Enable-PnpDevice -Confirm:$false
```

## 5. 已证伪的三条路（别再试，会浪费时间）

| 尝试 | 结果 | 证据 |
|---|---|---|
| 把遥控器改成 raw（老版「④ 改造遥控器」） | HID 接口不再注册，按键与音频全断 | 全系统 9 个 HID 接口、匹配遥控器 0 个 |
| 改绑成 `HID-compliant device`（新版 ④） | **打字符解决了，但 Raw Input 里没有这台设备了** | 客户机 14:48 日志：启动时认领 1 个 → 巡检时列表只剩 4 个 USB 设备；`enumhid_service=<empty>` |
| `--restore-keyboard` / 点 ⑤ | 删节点后**遥控器不会自动重连** | 日志 `已删除节点（下次连接会自动重新识别）` 之后再无实例 |

**根因**：Raw Input 的 keyboard 设备是 `kbdhid` 注册的。把它换掉，HIDClass 还在、TLC 还在，但**没有键盘功能驱动去注册输入设备**，所以 Raw Input 列表里就没了。

## 6. 不能做的事：复制开发机配置

配对记录里含**链路密钥**、设备实例 ID、适配器 MAC，全部**本机绑定**：

- `BTHPORT\Parameters\Devices\<MAC>\` 下的密钥不能跨机拷
- `Enum\HID\...\8&309e23b6&3&0000` 的实例号与本机适配器有关
- `ServicesFor<适配器MAC>` 的键名带本机适配器 MAC

**只能对比，不能搬**。搬过去的结果是配对失效、设备变未知。

---

## 7. 建议的执行顺序

1. **客户机**：重启蓝牙适配器 → 按遥控器 → 跑 `snapshot.ps1`，确认 `enumhid_count>=1` 且 `enumhid_service=kbdhid`
2. **客户机**：装 VB-CABLE → 确认 `cable_present=yes`
3. **客户机**：重启电脑 → WinUHid 就绪
4. 三点都绿后，再谈「打字符」——那时才轮到 `RIM_TYPEHID` 那条新路
5. **开发机**：也点 ⑤ 恢复 `kbdhid`，保持两组基线一致
